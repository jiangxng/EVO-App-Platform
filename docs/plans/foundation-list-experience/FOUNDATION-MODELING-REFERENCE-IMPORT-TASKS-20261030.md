## 1. 目标与顺序

业务顺序为 **2 字典 → 3 组织与人员 → 4 基础对象建模 → 5 基础对象数据导入**。上传并解析源文件可提前进行，用来发现缺失字段、字典值和引用；只有目标模型已发布，且所有必需依赖可用，才允许提交基础对象数据。

第一条纵向验收使用往来对象的三个字段：`客户等级` 引用业务字典，`负责部门` 引用组织，`负责人` 引用人员。字段名称只是测试业务样例，实施前应核对当前对象 owner 的真实语义和目标字段；不得为了样例修改核心字段含义。

完成状态必须分别记录：契约和代码检查、真实 Host 操作、桌面与手机体验、Human 签收、本地或生产部署。计划合入 main 不等于以上任一项通过。

## 2. 已有能力与明确缺口

- 基础对象已有 Core Schema、企业扩展字段和有效 Schema；对象页、导入目标和 API 应消费同一有效 Schema。对象的核心字段与不变量仍由对象插件拥有。
- Object Extension 已有企业新增字段及批量确认入口；当前新增字段操作主要支持 STRING、NUMBER、BOOLEAN、DATE。基础对象 Schema 还没有跨插件字典/组织/人员引用字段类型。
- Data Import 已有源文件、映射、预检查、提交、Recipe 等机制；本计划复用这些能力，增加清楚的“准备并发布目标模型”阶段及引用值校验。
- Host 的登录身份/成员资格不是业务人员名录；Responsibility 的负责人引用与人员模型需要经公开契约对接，不能直接借用登录用户表作人员主数据。
- Enterprise Context 保管企业定义的版本、归属和发布记录；字典、组织、人员和对象扩展插件各自拥有业务语义。Eidos 拥有页面模式、导航和视觉语言。

## 4. 插件与模型边界

1. **建模有三个层次。** 对象插件发布不可由导入文件随意改写的核心业务模型；企业通过 Object Extension 发布适用的新增字段；一次 Import Job 只保存源列到目标字段及源值转换的映射。三者有不同的版本和权限。
2. **先发现、后发布、再写入。** 源文件解析与样本预览可以先于建模。系统可以建议字段和字典值，但必须展示来源、目标、影响，由有权的人确认。发布目标模型后，Import Job 记录所用有效 Schema 版本或摘要。
3. **依赖按实际字段声明。** 不引用字典、组织或人员的简单基础对象仍能只用现有基础字段完成导入。引用字段要求相应插件已安装、激活且版本兼容；停用前检查已发布模型和数据引用，不得留下静默失效的字段。
4. **保持轻量 Host。** Host 只处理通用插件安装、能力发现、权限和调用。字典归字典插件，组织归组织插件，业务人员归人员插件，对象不变量归对象插件，导入作业归 Data Import，企业定义持久化归 Enterprise Context。外部 HR/LDAP/旧系统连接以后作为 Provider/Adapter 按实际迁移需求接入。
5. **界面使用业务语言。** 日常用户看到“准备字段”“选择字典值”“选择部门/负责人”等可操作概念；Schema digest、插件能力 ID 与内部状态只进入高级诊断或交付证据。V3 可作为业务清晰度参考，不能直接复制其 CSS 当作新插件设计系统。

### 6.1 建模与导入的状态及取消边界

建模流程：识别已有模型 → 保存拟变更定义 → 校验依赖与影响 → 有权者发布 → 取得有效模型版本。已有适用模型且无需变更时直接复用，不能强制重复确认或重新建模。

导入流程：解析源文件 → 关联有效模型 → 保存映射/值对照 → 预检查 → 明确提交 → 核对回执。源文件可先解析；只有发布及依赖条件满足才可进入正式写入。

建模草稿尚未发布时，取消保留或明确丢弃草稿；已经发布后取消本次导入，模型仍存在。发布成功但返回响应失败时，先按幂等记录读取实际结果，不能重复创建字段。导入期间补字典值或修正组织人员后，恢复原任务并重跑受影响校验。模型修改权限与数据导入权限分开；没有建模权限的人可保存待授权处理的任务，不能通过导入间接发布模型。

“建模”是工程和治理上的独立能力。Human 页面采用已批准的业务表达与渐进展开，让用户看见字段含义、类型、引用及影响；无需为理解技术生命周期而学习 Schema 或内部插件 ID。页面定义与恢复路径按 HX-01 先审查后编码。

### 6.2 与 Skill、MCP 和既有业务方法的关系

Skill 是可选的方法与知识贡献，业务插件拥有可执行规则和事实，MCP 是协议投影，微服务是可选择的部署方式。沿用 [扩展边界宪章](../../architecture/EXTENSION-BOUNDARY-CONSTITUTION-v0.1.md) 和 [Human + LLM 可操作性](../../architecture/HUMAN-LLM-OPERABILITY-v0.1.md)。[EA-5C MCP 基线](../../architecture/MCP-CAPABILITY-OPERATION-PROJECTION-EA5C-v0.1.md) 记载 READ/PLAN、未启用 WRITE；实施时核对当前实际准入，不能由本计划推定外部写权限已开放。

APQC 的流程分类与映射、复式记账的确定性约束、业财一体化的事实追溯、TOC 的约束分析和 PDCA 的试验评价，后续可消费这些稳定身份、版本定义和可追溯事实。它们不是本轮基础对象导入的强制插件依赖，也不进入 Host 核心。本计划先证明通用机制，后续业务专项依据自身 owner 与真实业务案例扩展。
