## 二、经确认的研究推导

1. **识别优于回忆**：显示历史映射、过去人工选择和当前候选；不要让人回忆原字段 ID、上一次为什么选它。M01。
2. **短时记忆受限，但不是「界面最多 4 项」**：Cowan 的纯短时记忆平均约 4 组块有明确实验条件，不能当软件按钮上限；应靠来源与系统决定的并排显示减少临时记忆。M02。
3. **必须缩短关键路径并保留返工通道**：W3C COGA §4.6.2、§4.6.3、§4.7.5 建议最少必须步骤、减少非必要选项、不依赖记住此前输入、可返回纠错。该工作组说明文件不是 WCAG AA 规范的强制附加条款。M03。
4. **中断即断点续作，不重做**：持续显示文件、已保存时间、已做决定和待处理问题；自动保留选择，下次回到原工作上下文。M04。
5. **年龄差异不能变成年龄标签**：NN/g 对 65 岁及以上用户跨年代的研究显示小字号、小点击区域、陌生术语等障碍，且数字技能随代际经验改善。默认清楚的标签与尺寸，不按年龄自动剥夺功能。M05。
6. **少步骤不等于少成本**：阅读、滚动、点击、跳页、切换注意力和依赖记忆均构成成本；「一页 22 个大下拉」未必优于两个清晰阶段。M06。

## 三、低记忆负担 V2：用户可见的两个阶段

### 阶段 A：上传资料

- 一个主入口「选择 Excel」，文件内容与来源列安全暂存，立即显示「资料已保存」。
- 自动按优先级：当前作业已保存决策、相同企业确认的历史映射、仍存在/可写的系统目标、必要时 AI 对未匹配字段的建议；AI 不能悄悄覆盖用户历史确认或无权限建字段。
- 后台执行并回到同一上下文，不要求用户理解 Import Job、Recipe、schema digest。
- 技术 ID、字段管理、AI 模型选项全部放到高级细节，不成为默认任务。

### 阶段 B：核对并导入（一个页面、内部两个状态）

**状态 1：核对**
- 头部保持「导入供应商、原 Excel 文件名、来源已保存、上次保存时间」。
- 首页显示真实已识别/拟新增/来源保留结果的分类摘要；字段计数只能来自当前作业，不能拿「22 未匹配」硬编码为「22 新建」。
- 只把真正的例外排在前面；每项保留原 Excel 列名、必要来源样本（权限/脱敏）、原人类决定、当前建议、为什么需要核对以及原地修改入口。
- 例如「开户银行：两个同名候选」只可由人选对目标；「主体类型：原历史三行缺失」须按这次真实作业校验，不得按供应商关系自动代填。
- 明细默认折叠，一个「查看全部字段与修改建议」可在本页展开所有来源列；不逐列跳完整新建表单。
- 主操作「确认字段并预检查」。如涉及新建企业扩展字段，必须展示完整待新建清单并取得一次明确确认，不能自动写正式 Schema。用户忽略仅是不写目标字段，原始值仍保留。

**状态 2：预检查 / 最终导入（仍在同一页）**
- 核对状态切换为预检结果区域，仍显示原文件、已保存字段决定、行号与失败原因。支持「返回修改」并原地恢复全部已做选择。
- 如果真实来源存在 3 行主体类型缺失，则提示确切问题行并提供合法补录/重新上传修复入口；不假造企业身份。
- 只有预检全通过、权限允许且字段定义已由人批准后，「确认导入供应商」主操作才可执行。最终确认与前述 Schema 创建确认彼此独立，但不用多次页面跳转。
- 用户离开、断网或隔天回来，可以定位同一作业和尚未解决的事项，不要求从头上传/重新匹配。已提交记录按受控业务修订与审计纠错，不能偷偷覆盖。

**为什么这是两阶段而不只是两次点击**：用户只需知道「上传」和「核对并导入」，但真正的 Schema 副作用、验证和正式提交仍遵守各自 Human 门禁。错误恢复不强迫用户重走所有步骤。

## 四、V2 视觉交互稿的内容顺序

1. 一级标题：导入供应商。文件名、已保存进度放在旁边，不显示 UUID。
2. 一个安静的摘要：系统已复用历史选择，尚有若干建议/例外，计数基于真实作业计算。
3. 仅必须处理的例外列表（真实状态驱动），一条事项的来源、建议、操作在同一行或同一个展开区域。
4. 一个次级文本入口「查看全部字段」，可检视和撤销已有决定。
5. 一个主操作「确认字段并预检查」；预检后同区域转换为「确认导入」，不可在失败时绕开校验。
6. 「已保存的草稿/继续上次工作」贯穿两阶段，关闭页面后不失忆；不要需要用户备忘录。
7. 字体以 16px 正文为推荐候选、支持缩放、清晰对比、可达控件、无倒计时；熟练者仍能主动进入完整字段明细。

## 六、重要冲突、产品边界与验收标准

- 「极简两阶段」不允许消除**批量字段创建前确认**与**最终供应商导入确认**；后者本质上不同的副作用。
- 「每一步需要上下文」与「避免首页过载」并不冲突：重要上下文常驻，已解决明细折叠、一键可见；用户不需要从记忆中寻找。
- Cowan 四组块不是「最多四个功能」的设计规范。年龄组均值不是判定个体记忆/注意力的依据，专业用户主动要求表格细节必须可用。
- 用户真实 Excel 22 未匹配列的实际分类尚无数据核实；任何页面示例中的其他统计均不能称为已计算。
- 真实验收：新旧两次上传；保存的映射是否可见、无需重选；中断并继续后能否恢复修改与原文；同名银行冲突和真实三行主体类型缺失能否原地修复；一对一约束、权限、显式确认均成立；移动/桌面/键盘与文字缩放完成任务，测完成时间、错误率、返回重做次数、注意力跳转次数。
- 代码边界：BEX 主体 apps/data-import 与 apps/object-extension；PA-02/PA-04 Agent、共享 Eidos 和全局平台治理不属于本设计 PR 任务。
- **下一步**：配套 V2 HTML 原型只作为交互评审，不是真实导入入口。经用户确认后再提出独立功能 PR，不移动 Railway 固定发布分支。

**总原则：系统保存上下文，用户只确认结果。**

### 7.3 补充的明确实施验收口径（不修改已确认业务规则）

1. **历史来源先于建议。** 先用当前 Job 已保存决定，再按企业/对象/版本兼容性恢复合法历史 Recipe/映射，再走可解释的确定性匹配与可选 AI 建议；不覆盖明确 Human 决定；失败不阻止人工路径。
2. **摘要数字来自真实 Job。** 明确区分“已有目标/待批量创建/仅保留原始值/待你确认”；同一来源不重复计数或隐式写入，按权限决定显示原始样例是否脱敏。
3. **例外尽量就地解决。** 同名候选给可区分的业务上下文和选择控件；缺失主体类型给准确行号与修复路径；不解决时主动作必须明确为何不能前进。
4. **创建与导入是两种不同副作用。** 批量新增企业字段前展示所有字段及类型并取得一次 Human 确认；dry-run 通过且权限成立后，仍需另一独立“确认导入”动作。具体先创建/先预检的服务状态契约应沿现有 Host 受控语义验证，不能悄悄调整顺序。
5. **草稿恢复与验证失效。** 中断/重新登录/第二次导入可见当前作业来源、历史决策与保存时间；修改映射或字段定义后须使旧 dry-run 结果失效，重新预检才能提交；已正式提交的数据只能走受控审计修复。
6. **真实全量审阅。** 默认只展开必须判断的例外；可在当前页面展示每个来源列和允许的有效目标；“忽略”只影响业务写入，仍保留授权范围内原始列值且可撤销。
7. **多端、跨年龄和可访问性证据。** 同一业务任务在桌面、窄屏、键盘、屏幕阅读器及 200%/400% 缩放场景完成；核对正文 4.5:1、适用 UI 非文本 3:1，触控区域 44px。不得按年龄自动降低功能。
8. **实机验收量化。** 用原 Excel 与 `import-33ff3446-80c5-4992-b5c6-710f415535b3` 比较首次导入与复用、需人工确认项数、操作耗时、错误率、撤销成功、中断后恢复、一对一约束、同名字段判断、三行主体类型修复。测试环境为现有 Railway 开发环境，部署固定已通过 CI 的准确 SHA，严禁盲目部署移动 main。
