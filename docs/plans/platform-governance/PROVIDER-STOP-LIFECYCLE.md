# GOV-02 Provider异步停用状态与重试

2026-10-13。继续治理PR #796，基线已同步main `56a2ae52`，保留Agent窗口已合并内容。本批只调整宿主通用生命周期辅助器、宿主退出时的错误处理、对应测试及本专项文档。

## 已落地行为

`manager/lazy-provider-runtime.ts`现提供`diagnostics()`返回进程内快照：

| 状态 | 含义 | 是否允许新调用 |
| --- | --- | --- |
| IDLE | 尚未加载或加载失败，可重新加载 | 仅插件已激活时 |
| LOADING | 实现正在初始化 | 已激活时共享初始化 |
| READY | 实例已就绪 | 仅插件已激活时 |
| STOPPING | 等待已接收操作完成，随后清理实例 | 否 |
| STOP_TIMEOUT | 调用方等待超时，原任务仍在运行 | 否 |
| STOP_FAILED | 清理失败，保留原实例供重试 | 否 |
| STOPPED | 实例清理完毕 | 仅插件已激活时重新加载 |

同时返回activeCalls、blocked、cleanupPending和stopAttempts。快照不含业务内容或原始错误，不等价于持久审计记录。stopAttempts统计新等待轮次，不是实际dispose次数；并发stop共享同一等待。

stop默认最多等待30秒，可用stopTimeoutMs配置正整数毫秒。超时以PROVIDER_STOP_TIMEOUT拒绝当前等待，不强制终止业务，不清空实例，不将状态假报为STOPPED。

- 超时后调用stop，继续观察同一个清理任务，禁止并发重复dispose。
- 原任务迟到完成会自动进入STOPPED；迟到失败进入STOP_FAILED并保留阻断。
- 清理确实失败后再次stop，重试同一个实例的dispose；dispose实现应支持失败后重试。
- 加载过程中停用，迟到初始化不会再执行业务操作，但仍须释放新建实例。
- 瓶颈分析Provider既有停用接线自动使用新机制。宿主退出时即使该Provider停止失败或超时，也会继续清理进程插件宿主，并以非零退出码报告不完整关闭。

## 接口边界与后续

这是Host内部可查询状态和Promise回执，不是已经上线的管理员状态页面、公开重试API或持久生命周期任务。不能把同步的“插件已停用”返回值理解为异步资源释放完成。

下一批接入统一管理员查询/重试入口前，应先确定授权、包到运行实例的注册关系及审计事件；重试仅允许清理失败或继续等待既有停止任务，不能借重试重新启用插件。不要为每个插件新增一套独立按钮或接口。

本轮没有强制取消业务调用。外部IO仍需Provider自身支持AbortSignal/请求超时，写事务取消、幂等补偿、进程强制退出边界另行设计。无资源的瓶颈分析Provider继续作为首个接线试点；第二个有资源Provider迁移尚未完成。Node模块缓存不因stop卸载。

不修改Agent专项、全局project.status或全局HANDOFF；本入口及PR记录作为下一窗口接续依据。
