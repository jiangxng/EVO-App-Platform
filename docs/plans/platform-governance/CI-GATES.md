# 轻量宿主 CI 门禁

2026-10-13，用户明确要求将架构作为CI校验。本轮在PR #794同一分支继续，不另建开发线。

## 已实现

工作流 `.github/workflows/lightweight-host.yml` 在所有PR、main推送和手动触发时执行，权限仅contents:read。检查名 `lightweight-host`。本地命令：`npm run architecture:lightweight`。

1. 从 `manager/server.ts`、`catalog/seed.ts` 递归解析本地运行时依赖。先擦除TypeScript类型，识别静态import、export转出、require及直接模块级动态import；追踪间接转出，不能用中间文件隐藏新增业务依赖。
2. 对指向apps/providers/agents的依赖边建立精确遗留清单。新增边失败；已移除的边必须同步移出清单。CI对比目标提交，禁止通过扩大清单放行新增依赖。首次引入清单时，对固定目标提交代码现场计算并核对，不盲信当前PR的清单。
3. 运行现有模板商店/2D资源懒加载约束，以及未激活、依赖未激活均不加载动作实现的行为测试。
4. 新增并发首次调用共享一次加载、失败后重试的行为测试。

## 覆盖限制与下一步

- 这是防止依赖扩张的第一批门禁，不是已实现完整轻量宿主的声明。
- 不分析完整调用图：函数内import由业务测试验证；立即调用函数中的动态import、模块别名、外部npm包及同文件新副作用尚不能完整覆盖。禁止把加载放入启动时调用的函数来伪装按需加载。
- 新入口/别名机制需要同步扩展检查器及回归测试；纯元数据新增依赖也会被保守阻断，应先建立明确的元数据隔离机制，不能默默放宽基线。
- GOV-01继续测量实际启动、RSS、连接、定时任务、活跃实例；GOV-02补停用释放、并发启停与恢复行为测试。不能以菜单不可见代替资源释放。
- 工作流失败会使检查标红；仓库分支保护是否把 `lightweight-host` 列为必需检查尚未配置/核实，不能宣称管理员也无法绕过合并。

后续每批治理应缩减对应遗留边，保留正常认证授权，并用实际资源证据证明改善。
