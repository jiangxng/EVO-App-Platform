# GOV-02 首个按需加载试点

2026-10-13，基于 `ae59343c9db0291716defe74fa61535e10a1aeb6`；继续PR #794。状态：瓶颈分析Provider加载/启停试点完成；真实连接或后台任务资源释放仍待后续试点。

## 本轮改变

宿主不再静态导入和启动时创建 `eog-bottleneck-analysis` 实现。注册的只是轻量接口，首次已激活调用才动态加载、创建分析器。发现能力和展示目录无需创建分析器。

通用机制位于 `manager/lazy-provider-runtime.ts`，属于宿主生命周期职责；业务分析算法仍在Provider内，未移入Core。

- 未激活时拒绝调用，不加载实现。
- 首次并发调用共享一个初始化Promise；失败后可重试。
- 停用/卸载立即阻止新调用。加载尚未完成时，等待加载结束但不执行新业务操作。
- 已进入的调用按drain策略完成后，执行可选dispose并清除实例引用。
- 停用未完成时即使重新启用，也不允许新调用穿过停止阶段；完成后下一次调用重新创建实例。
- dispose失败时保留实例、阻止复用；后续stop可重试清理。
- 宿主生命周期事件和退出流程接入stop。停用API本身仍是既有同步生命周期接口，不承诺响应返回时异步drain已经结束。

Facade初始健康为UNKNOWN，避免把“可加载”伪装成“实现已健康运行”。本轮不增加监控界面或新公开接口。

## CI与证据

6项专项测试覆盖未激活不加载、并发共享、加载中停用、执行中drain、并发停止共享、清理失败阻断与重试、重新激活、真实分析器空证据调用以及宿主接线。停止资源测试使用可观察的测试dispose，不冒充真实数据库资源试验。

静态依赖门禁实际移除2条提前加载边，遗留清单299→297。移除的边必须从清单同步删除，未来重新引入将使CI失败。工作流同时执行现有启动/安全恢复测试及三组资源基准。

## 限制与下一步

瓶颈分析器是只读、无持久连接/后台任务的服务，本轮验证按需创建与实例生命周期，不宣称数据库连接回收或特定内存节省。Node模块缓存不会被stop卸载。

通用stop尚无强制取消或drain超时，当前试点仅适合有界只读调用；推广至外部IO、流式任务或写操作前，必须增加超时/取消策略与明确回执。停用完成状态未来需与管理员界面及异步生命周期回执对齐。

下一步选择一个具有可隔离连接/订阅资源的非关键Provider，验证资源创建、实际释放、超时与失败恢复；不直接迁移身份/权限/凭据和正式账本。继续缩减静态依赖，不把安装包减少等同实现完全按需加载。
