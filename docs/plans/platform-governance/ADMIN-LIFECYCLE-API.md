# GOV-02 统一生命周期管理接口

2026-10-13，继续PR #796。提供统一的Host管理API，首批注册瓶颈分析Provider；后续资源Provider通过同一个注册表接入，不逐插件新增一套接口。

## 接口及授权

- `GET /v1/providers/lifecycle`：查询全部已接入的实例；可用`?packageId=...`筛选。查询不加载实现、不激活插件。返回的IDLE注册项可能尚未安装，注册不代表已安装或运行。
- `POST /v1/providers/lifecycle/retry-stop?packageId=...`：等待已有停止任务或重试清理失败。仅blocked实例可执行；正常运行、未加载、已停止返回409，不能用此入口发起新的停用或启用。
- 通过Authorization Bearer头提交既有Host bootstrap管理员凭据；不接受URL中的令牌。管理员认证和策略授权都必须通过。策略动作分别为`provider.lifecycle.read`和`provider.lifecycle.retry-stop`，资源为`provider-lifecycle`，可按packageId授权。
- 本地体验配置增加这两个动作；正式自定义策略需要明确授权，未配置默认拒绝。沿用既有管理员认证，不另建身份系统。

返回：200成功；403未授权（先鉴权再查询，避免泄漏包是否存在）；404未注册；400重试缺少packageId；409无待清理任务；504等待超时仍保留阻断；500清理失败仍保留实例。响应不返回原始异常或业务内容。

## 审计与安全边界

复用provider治理审计存储，记录查询/重试的允许或拒绝、操作者、策略来源和包ID。重试另记录清理结果码；ALLOWED表示授权通过，不代表释放成功，应读取PROVIDER_STOP_RESULT的reason。审计写入失败时不开始重试。默认JSONL路径沿用已有provider-governance-audit.jsonl配置；未配置持久状态时使用内存存储。

生命周期状态本身仍是进程内快照，不是持久任务队列。请求断开不终止已经接受的清理；重试共享底层任务。只能管理注册过且遵守停用契约的实例，不代表全平台已治理完成。

## 验证与下一步

4项专项协议测试验证认证/策略拒绝、查询不加载、非法状态不能发起停用、失败清理可重试、审计失败阻断、超时状态及异常脱敏。真实Host HTTP测试验证匿名拒绝、管理员只读查询、IDLE重试被拒；原有最小启动和恢复测试继续通过。轻量Host CI增加该协议测试；静态业务提前加载边仍297条。

本批完成管理API，不宣称管理页面已完成。下一批在现有Provider管理页面呈现统一状态和按状态启用的重试操作，复用eidos组件与管理员权限，再选择第二个有资源Provider迁移。Agent窗口仍独立推进；本批不变更Agent能力和启用条件。
