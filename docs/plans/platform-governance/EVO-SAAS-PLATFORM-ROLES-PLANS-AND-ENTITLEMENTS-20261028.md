# EVO SaaS 平台用户、企业创建授权、套餐与插件权益方案

**日期：2026-10-28；状态：研究与设计提案，未实施、未定价、未上线。** 这是同工作线原 IAM 规划的扩展，不是第二套权限体系。研究来源、访问等级、比较和链接见同目录 EVO-SAAS-ROLES-PLANS-EXTERNAL-RESEARCH-INDEX-20261028.md。

## 1. 用户明确要求

EVO 平台超级管理员可以管理平台用户，并给普通用户 A 单独授予“创建企业上下文”的能力；A 创建企业后自动成为该企业的超级管理员。EVO 要提供多个套餐供用户选择。所有业务插件按需安装，平台与企业权限清晰分开。

**永久规则**：平台超级管理员 / 企业所有者 / 创建企业资格 / 财务管理员 / 付费功能权益是不同的概念。任何一项都不能自动授予其它几项。

## 2. 管理权限的正确层级

| 资格/角色 | 范围 | 权限 | 严格边界 |
| --- | --- | --- | --- |
| 平台超级管理员 Platform Owner | EVO 平台 | 管全部平台用户、创建资格、套餐、订阅、平台插件审核、运维审计 | 不默认进入其它企业查看业务数据 |
| 平台运营/支持管理员 | EVO 平台 | 只按委派处理账号、订阅、安全、支持、插件 | 不能给自己全权或无审批访问客户数据 |
| 平台财务管理员 | EVO 平台账务 | 套餐目录及账单运营 | 不自动具有安全或租户数据权限 |
| 创建企业资格 Tenant Creator | 单个用户 | 受有效期和数量限制创建企业 | 不能管理平台、不能访问别人企业 |
| 企业 OWNER（创建人默认） | 指定企业 | 企业成员、管理员、授权、业务应用、转移所有权 | 不等于平台超管、不能跨企业 |
| 企业 ADMIN / 应用管理员 | 指定企业/应用 | 管获授权的成员、业务模块和角色 | 不可转移 OWNER 或突破企业套餐 |
| 企业 Billing Manager | 指定企业订阅 | 套餐、席位、用量、发票 | 不自动读取业务数据 |
| 企业成员/审计员 | 指定企业 | 各自操作/只读 | 无权访问其它企业或超出动作 |
| Agent/Service | 受托 Principal | 有时限、范围和撤销的授权操作 | 不自动继承用户或平台全权 |

建议企业至少一个有效 OWNER，支持将 OWNER 转移和添加企业 ADMIN；不要将“创建企业”作为永久平台超管属性。共享东京 demo-user 不能作为正式生产身份。

## 3. 用户 A 完整工作流

1. 平台超级管理员打开“平台管理 → 用户 → A → 平台授权”，授予 create-enterprise 资格，可设置最大企业数、到期、审批要求。权限与配额独立保存，留完整审计记录。
2. A 用真实个人身份登录，进入“我的企业 → 创建企业”。系统**先做资格预检**：账户有效、创建资格仍有效、企业数未达到配额、没有风控/停用阻断。无资格时显示“申请开通”，不是提交后暴露 STATIC_POLICY_NO_MATCH。
3. A 输入企业信息并选择可购买的套餐（如 Free/Team/Business/Enterprise）或试用；显示席位、可用插件类别、AI/自动化限额及账期。不要要求先安装客户管理/采购等业务插件。
4. 后端事务化创建 Enterprise Context、OWNER 关系、Grant、初始订阅/试用权益、默认企业选择、审计和幂等记录。所有步骤成功才提交；失败回滚，避免孤儿企业或超额竞态。
5. A 自动成为新企业的唯一初始 OWNER，有权限进入“企业管理”。以后可委派 ADMIN、Billing Manager、邀请 B，并按需求安装/绑定业务插件。
6. A 再创建企业乙时须再次校验其可创建数量和资格；企业甲/乙各有独立套餐、权限和数据。A 在乙有 OWNER 身份不能让甲成员 B 自动看到乙的数据。
7. 撤销 A 的继续建企业资格**不删除**已创建企业，也不自动撤销其现有企业 OWNER；若要回收 OWNER 必须走企业治理和所有权转移。

## 4. 套餐/许可/权限四层必须拆分

- **Plan**（套餐目录）：Free/Team/Business/Enterprise 的可售 SKU、价格版本、计费周期与默认功能包；价格由商业决策确定，不能照抄竞争对手当前金额。
- **Subscription**（企业订阅）：企业实际购买/试用/欠费/宽限/停用状态，按企业单独计费；创建人个人账户拥有多个企业不代表共享一份订阅。
- **Entitlement**（企业权益）：允许的插件功能、席位、企业容量、API/AI/存储/自动化额度、附加包。购买/升级/降级按生效时间决定。
- **Authorization**（用户权限）：成员关系、OWNER/ADMIN/自定义角色和资源级操作权限，必须限制于指定企业；付款成功不能授权某个人随意编辑业务数据。

**操作判定＝有效用户身份 ∩ 正确企业范围 ∩ 企业订阅/额度 ∩ 插件已安装且该企业已绑定/就绪 ∩ 该用户动作/资源授权**。不足分别给出“未登录/没创建资格/额度不足/需升级套餐/应用未安装/未绑定企业/缺少权限/服务不可用”友好提示。服务端每次操作独立重检，不能只隐藏按钮。

## 5. 套餐模型（名称和权益均为建议，不是已发布定价）

| 套餐 | 适用客户 | 可配置的权益方向 |
| --- | --- | --- |
| Free 免费 | 体验与微型团队 | 有限席位、存储、自动化、AI 点数；平台创建企业资格另验 |
| Team 团队 | 小团队协作 | 更多席位、常用工作流、基础角色和应用 |
| Business 商业 | 发展中企业 | 自定义角色、审计、API/集成、更多自动化和 AI 额度 |
| Enterprise 企业 | 大型与合规客户 | 企业身份集成、企业级安全/保留/SLA、专属部署选项、合同级额度 |

推荐商业组合：**基础套餐 + 增购席位 + 可选付费插件/附加包 + AI/自动化/API 使用额度**。试用到期/降级时保证已有数据不被自动删除，限制超额新增并允许查看订阅、续费与合规导出。AI 成本应可预算、限额和预警，不能在低价包提供无边界推理。

前期先建立可审计的套餐与权益模型，允许人工授权试用/人工账单；不要一开始自行开发复杂国际支付税务。以后可使用支付 Provider 与 Webhook 幂等同步订阅，账务系统**不是**用户动作权限的唯一判断来源。

## 6. 用户界面（基于现有 Eidos + 插件架构）

### 平台控制台：只对拥有平台级权限的人员出现

- 平台用户（账户、邀请、禁用、身份验证状态）
- **创建企业资格**（授予 A、剩余额度、过期、批准/撤销、审计）
- 企业/租户列表（名称、OWNER、创建时间、套餐、状态；不直接列出客户业务详情）
- 套餐目录、附加包、权益与用量限制
- 企业订阅与账务管理、优惠/人工调整审批、用量报告
- 插件上架与安全审核、平台管理员与运营角色、系统审计

### 我的企业：普通用户

- 已加入的企业列表和个人在各企业的身份
- 有创建资格时显示“创建企业”（无资格可申请开通）
- 当前试用/订阅/创建申请状态

### 企业管理：仅对当前企业有权用户开放

- 企业资料/Owner/管理员/成员与邀请/角色
- 企业已安装插件及企业绑定就绪状态（安装 ≠ 绑定 ≠ 可运行）
- 角色对应用操作和数据范围的授权；基于每个插件声明的 Action/Resource
- 当前套餐、席位、用量、增购与账单（只对 Owner/财务授权可见）
- 企业活动日志、安全与外部访问

**架构归属**：平台基础控制面拥有用户、企业创建资格、套餐与订阅 Authority；Enterprise Context Governance Experience 只提供企业治理管理 UI，Eidos 呈现；Provider 保存并执行企业授权与 Grant；业务插件声明资源/动作、按需安装。不得让可卸载的业务插件持有唯一的平台授权、账务或核心企业数据。

## 7. 必须特别防范

1. 平台超级管理员不等于全部客户数据超级管理员；必要支持访问需审批、限时、可审计。
2. 资格配额与企业套餐分别检查；不因购买高套餐自动获得在平台无限创建企业的权利。
3. 不让企业创建事务只生成 Context 而遗漏 OWNER、Grant、初始订阅或初始审计；并发双重创建必须幂等。
4. 企业取消订阅不删除 OWNER/Grant/业务数据；企业暂停、宽限和数据导出政策独立。
5. 会员席位按**具体企业**计算，同一自然人可加入多家企业，授权不能跨企业传播。
6. 企业/平台管理员的高风险操作需要二次验证及防锁死措施。
7. AI Agent 不可从自然语言请求自动升权，不得复刻另一套 PA05 身份权限。
8. 不默认安装业务插件；选择套餐只决定许可范围，不直接安装或初始化业务数据。
9. 所有权限/权益/企业绑定状态应在界面操作前预检，并在 API 强制重检、审计。
10. 生产环境不使用东京 Basic Auth 的共享 demo-user 预览权限规则。

## 8. 实施分期及验收

| 阶段 | 功能 | 验收重点 |
| --- | --- | --- |
| S0 设计确认 | 平台/企业角色矩阵、建企业资格、套餐与权益边界、PA05 现有能力对齐 | Product review 及负面用例确认 |
| S1 平台资格和首家企业 | 平台用户 A 创建资格、配额；我的企业；创建后 OWNER+Grant+试用权益原子创建 | 无资格/超额拒绝；A 成为自己企业 OWNER；不跨租户 |
| S2 企业治理与基础套餐 | 企业成员/角色/邀请、四类套餐草案、席位/用量展示、手工订阅 | 权限变更/租户切换/超额/降级及宽限实际验收 |
| S3 插件权益 + AI 用量 | 应用按需安装与企业绑定、权益判定、AI/API 点数/预算、插件附加包 | 权益、会员角色、插件状态变化独立生效，不互相替代 |
| S4 正式商业化 | 支付/发票 Provider、企业身份集成、审计/合同与高级隔离 | 账单幂等、续费/取消、数据保护、Human 实测 |

工程门禁：每步独立 PR + exact SHA CI + 路由与权责架构检查；若要部署须另行验收公网和 Human，不改 Railway 或未授权生产数据。与原权限管理规划、Eidos owner、PA05 owner 复用现有边界。

## 9. 需要产品确认而不能猜定的项目

Free/Team/Business/Enterprise 名称是否采用、试用时长、每包免费席位、AI 点数、企业创建数量、是否开放自助建企业或仅平台审批、增购规则、过期宽限和 Owner 与账单管理员是否默认同一人。全部属于未确认价格/运营决策，不在代码硬编码。
