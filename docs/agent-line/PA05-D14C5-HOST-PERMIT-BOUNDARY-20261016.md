## Decision and trade-offs

**Adopted — separately authenticated SQL Host, DB-protected ephemeral per-effect permit and original Owner transaction.** An administrator explicitly installs optional D14C5 constraints on the *real* `pa02_contexts`, `pa02_definitions`, `pa02_owner_evidence` tables. An independent least-privilege Host LOGIN, not the Business Owner LOGIN, can EXECUTE the SECURITY DEFINER issuer. The issuer checks the original D10 immutable ticket, PA-02 INVOKING/UNKNOWN and D14A local ACTIVE, and writes an unpredictable per-effect permit into a SQL table hidden from Business Owner. Original Owner receives the opaque permit from a Host-only adapter (not from Agent input), carries it in the same physical business+evidence transaction, and SQL checks the protected matching row. An immutable Owner-evidence INSERT atomically consumes the permit; deferred constraint triggers deny committing fresh Context/Definition rows without corresponding original Owner evidence. Previously consumed permit never enables a second material WRITE. Only one outstanding permit per scope/effect; ambiguous unconsumed issuance fails closed pending reconciliation.

**Rejected — GUC-only proof:** anyone holding the business SQL credential can SET LOCAL the same keys. **Rejected — application-wrapper-only admission:** the prior direct Owner bypass was already demonstrated at D14C3. **Rejected — granting business Owner token-table read/execute:** defeats separation. **Not asserted — multi-database global consensus, machine-attested Host login, or automatic key rotation:** none exists here. Tokens are deliberately short-lived (two minutes for physical writes), so delayed legitimate effects fail closed and need independent reconciliation; do not blindly reissue UNKNOWN.

**Residual limits:** the opt-in PG table guard cannot stop a privileged schema/table owner/superuser disabling triggers. Compromise of both independent Host and Business credentials or leakage of a not-yet-consumed permit is not covered; DB principals require real secrets distribution/network isolation. If a remote still reads ACTIVE under network partition, a previously staged ticket and its independently issued permit may still be effective locally until consumed/expiry. There is no global XA/2PC, no authenticated production Host/Provider/Human/Agent launch, no production migration of file-backed Object Extension, no default Host route change and no signed-off production WRITE.
