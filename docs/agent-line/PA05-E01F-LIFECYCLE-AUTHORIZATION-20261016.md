## Selected smallest fail-closed route guard

For exact `evo-purchase-attention` only, require existing configured bootstrap-administrator Bearer credential and independent current Authorization Provider **per lifecycle operation** before any package mutation. The policy action is `host.plugin.lifecycle.install|enable|disable|uninstall|upgrade` on `plugin-package:evo-purchase-attention`, attributes `effect=READ`, `operation=<OP>`, `admission=LIFECYCLE_ONLY`. Guard **all** five direct mutation endpoints and plugin-store Action command envelope for exact target package; never trust `confirmed:true`, `trustApproved:true`, `itemId` as authority. Fail closed to 403 `PA05_E01F_LIFECYCLE_ADMIN_DENIED` on no/wrong credentials, policy missing/deny/error. Apply the check before the first possible mutation. Existing unrelated packages are unchanged and remain subject to their own lifecycle architecture; this PR **does not** claim to certify the entire plugin management plane.

No silent auto-install, no changing allowed package IDs in E01D, no new default Host startup dependency, no preconfigured test policy in production, no new production WRITE. Explicit Host administrative approval remains distinct from the actual installation plan/lifecycle. A code-level guard must not replace genuine human consent and live identity signoff.

**Rejected:** patching only `/v1/install` (Action bypass), changing every generic plugin route as part of one PA05 slice (parallel owner compatibility risk), depending on JSON confirmation, assuming a test token identifies an actual Human, or weakening existing lightweight/PG18 architecture gates.
