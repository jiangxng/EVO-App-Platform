## Bounded decision

**Adopt:** in optional installed Object Extension three-real-table SQL gate, use a Host-owned `SECURITY DEFINER` role attestor with `search_path=pg_catalog`. Execute the same attestor **inside the real Host-only one-effect SQL permit issuer and inside the original business table physical trigger**, rather than trusting initial installer checks or an optional application wrapper. Both real SQL LOGIN roles must remain non-privileged, with no role-owner/escalation via delegated memberships (including NOINHERIT), no database/schema owner status, no direct DML or read access to the remote ticket/write/freeze state, no table owner/trigger/schema create abilities, no Host DML on actual Object Extension tables, no Business visibility/mutation of the Host-only permit table, and no Business EXECUTE of the Host-only issuer even if granted to PUBLIC. Require actual complete inventory of exactly the original three business tables plus Host permit table and three existing D10 Worker tables.

**No second Owner, receipt engine, default Host registration, replacement of D9/D10 or production data migration.** A committed role change is detected at next issuance and business physical insert; restoring safe grants permits the still-authorized original Owner to complete its genuine atomic resource+immutable evidence. There is no attempt to solve concurrent DBA GRANT/REVOKE atomically across independent databases.

**Alternatives rejected:** one-time installer audit (TOCTOU after GRANT), optional JS preflight only (untrusted direct SQL bypass), and treating a NOINHERIT grant as harmless (SET ROLE remains a relevant privilege-escalation path). No global guarantee against SQL superusers or a table/schema owner disabling/replacing the checking functions and triggers.

## Real acceptance and explicit negative evidence

The prior [C5 dedicated PG18 test](../../tests/agent-line/pa05-object-extension-host-permit-pg.test.mjs) is extended **without cloning an engine**. Re-use three distinct PG18 `system_identifier` values, the original Object Extension Owner/verifier and real D9/D10 ticket. Before new Host issuance, grant UPDATE on Worker `pa02b_writes` to the Host SQL LOGIN and confirm denial, then revoke. Grant a NOINHERIT delegated Worker UPDATE role to Business LOGIN and confirm denial, revoke and drop the role. GRANT EXECUTE on Host permit issuer to PUBLIC and confirm denial; REVOKE restores issuance. After a valid Host permit exists, grant SELECT on protected Host permit table to the Business SQL LOGIN and confirm the actual business INSERT trigger rejects it; revoke the dangerous grant, then original deferred receipt invariant must still reject a business-only commit. Finally the real Owner's legitimate business+receipt transaction succeeds, idempotency and local freeze remain guarded, and the privileged DBA counterexample still passes as an **unsigned bypass**. New CI marker `PA05_ACTUAL_OBJECT_SQL_ROLE_DRIFT_PG` is mandatory in addition to old D9–D14C5 markers and zero skips.
