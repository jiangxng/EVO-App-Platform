# Agent 开发交付与分支治理规范

Status: ACTIVE_POLICY_PROPOSAL_IN_PR_823
Scope: EVO-App-Platform 的 PA / External Agent 独立开发线。其他 owner 的分支不得代为更改或删除。

## 目标与原则

**以功能闭环为进度单位，而不是 PR、分支、提交或验证次数。** 已有功能应成为可信的可复用资产，而不是每次新开发都重新审查全部代码。每项 Agent 交付必须同时能说明：目标、改动的接口、原有契约、差异、通过的验证、未完成的门禁、合并提交和分支清理状态。

- **一项任务，一条活动开发主线**：同一 PA 工作包默认只用一个活动开发分支/开放 PR；在其上连续提交、修复和重跑 CI。不得为每个函数或新增测试再开枝。
- **短闭环入 main**：达到一项明确可回归交付，CI 合格即合入 main、核验 GitHub merged 和内容去向，清理临时分支；下一项从最新 main 起步。功能未全部结束不意味着必须保留长期总分支。合并代码不等于产品完整或上线。
- **安全的例外**：仅有不同 owner、无高冲突文件、独立可验证、可说明合并顺序与退出时间的工作，才允许同时开独立分支。分支创建前写明所依赖的现行 PR；不允许多个窗口争改同一 `manager/server.ts` 片段。
- **无重复开发**：开始先查最新 main、现存 PR 与未合并分支；找到同功能后续用已有分支。复用已验证旧能力时优先依赖接口、合同与 CI 证据；只在接口变更、契约未覆盖、安全边界变化或回归失败时定向深入旧实现。不得因为换窗口重做相同研究和隔离实验。
- **无悬空分支**：活动分支必须关联可追踪的 PR / 任务；有后续独有提交的子分支必须在父 PR 结束前收敛。合并受阻就在原分支重对齐主线、重新获取 required checks；不得新建分支绕过 GitHub 保护规则。
- **已合并即清理**：同仓合入 main 后，自动清理流程必须核对 PR `merged`、head SHA 不变、head 属于 main ancestry、无其他开放 PR 占用、不受保护；任一条件不成立只报告不删除。分支还存在不等于业务功能未完成。
- **不得丢失独有内容**：未合并/历史分叉分支逐条核对独有提交及与 main 的实际内容。确认已吸收/明确舍弃并记录理由之前禁止直接删除，更不能强推/改写 main。
- **阶段只按原始验收清单收口**：PA-02 的 R01–R10、Run/Receipt/Worker/Owner/Cancel 形成可运行闭环后，记录开发阶段完成；生产迁移与发布另设门禁。不以新增实验、再次通读旧代码、更多 PR 数量为“前进”。
- **轻量宿主和安全底线不变**：Host 默认不启用未完成执行模式；验证真实租户隔离、作用域与权限、未知写入不盲重试、终态不能凭模型文本编造；生产发布仍须单独授权。

## 固定工作节奏

| 时机 | 必须留下的事实 |
| --- | --- |
| 开始前 | 最新 main SHA、现有 PR/分支、既有契约/测试、要闭合的阶段 gate，证据来源 |
| 开发中 | 继续使用一个工作分支和原 PR；重复的旧测试只跑回归、不重新造实现 |
| 合并前 | 明确本次新旧影响范围、最小相关 CI、负向权限/并发关键回归、提交归属 |
| 合并后 | GitHub merged 与最终 SHA，独有代码是否进入 main，删除源分支的 GitHub 状态 |
| 每次交接 | 当前所有 Agent 开放 PR、无 PR 独有分支、已合并未删分支、阶段剩余 gate 的数目及依据 |

## 自动化执行边界

复用现有 `.github/workflows/branch-hygiene.yml` 而不再为每个 PR 生成一次性清理 workflow：

1. 每日/手动审计 Agent 相关分支：显示是否有开放 PR、与 main 的唯一提交、是否落后、是否因无 PR 而产生无人认领的交付；超过 24 小时仍有独有提交且无开放 PR 的分支在定时审计中报错。**审计不删除分支**。
2. Agent PR 合并进入 main 时，自动尝试 **仅删除该 PR 的精确不变 HEAD 引用**；对 squash、分支变动、不同仓库、其他 PR 使用中、主线未包含原提交等情况 fail-closed。无法自动删除时报告并人工核对，不伪称完成。
3. 不绕过受保护分支、不强制 push、不执行自动合并、不重新部署生产。旧的手动退休清单和非 Agent owner 的清理流程继续保持各自边界。
4. 自动流程是分支治理，不是代码重复扫描、源码质量与业务门禁的替代品。
