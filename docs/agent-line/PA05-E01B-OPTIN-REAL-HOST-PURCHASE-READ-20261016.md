## Decision and controlled change

Retain the original shared [`manager/server.ts`](../../manager/server.ts) byte-for-byte. Do **not** add a startup conditional catalog import, default installation, env-driven product enabling, alternate Action Router or separate Agent tool registry. The guarded production Host remains entirely uninfluenced by E01B.

Add only a [plugin-owned lazy Host adapter](../../apps/purchase-attention/host-optin.ts): it exposes the existing Package manifest for a **future owner-authorized on-demand composition**, and creates a `createLazyAppActionHandlerV010` for `purchase.attention.read`. It resolves the shared source Action Router **only during an actual invocation**, then delegates to the original Purchase Attention Owner which invokes `trading-reference.purchase-operations.read` through the **same** Router. Thus both source and derived Operation still require their own active Features, package installation, current enterprise/resource policy and authorization Provider. No runtime deployment or default module expansion is introduced.

**Changed from initial E01B approach, and why:** the conditional startup import was removed on the same PR after **actual architecture CI rejected it**. An opt-in flag is not a sufficient substitute for lazy activation. A future real Host integration must use a genuine on-demand plugin loader with reviewed architecture/permission semantics, not an eager loophole. This is not a reversal of the previous E01A decision against unapproved production installation: E01B implements **only an adapter readiness layer**. Full live E01 remains open.

**Rejected:** suppressing the architecture ratchet; adding one extra business module to the default Host startup graph; creating a second router; calling `manager.install` an executed production binding; fictional Human or Provider identity; direct source Owner service shortcuts; enabling WRITE/PKI.
