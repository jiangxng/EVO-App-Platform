## 2026-10-20 — Shutdown error-path source audit (read-only)

Current main `manager/server.ts` exact blob `d1c50cc2c4c52bd251146ce84dfc6acfeca45e53`, lines 10224–10259, confirms SIGTERM/SIGINT handlers and the intended cleanup order. A second, narrower issue is visible in the actual shutdown implementation: only the scheduler and grouped managed-runtime stop sections have local `try/catch`; the subsequent awaits for optional Agent reader/worker, optional PA-02 Owner, PA05 lifecycle Host, and process runtime Host are unguarded and sequential. `server.close()` and the 5-second fail-fast timer are reached only if those awaits resolve.

**Source fact:** a rejection from one of these later close operations can short-circuit the remaining cleanup and prevent the code from reaching `server.close()` and scheduling the explicit fail-fast timer. Because the cooperative lock releases only on a clean process exit, this should remain fail-closed (lock retained for independent review), but it does not provide a complete per-resource shutdown receipt.
