## 12. PA05-04B transactional lifecycle fence — isolated engineering candidate (2026-10-15)

**Identified source race:** The existing trusted PA-02 Host transitions `pa02b_writes.PREPARED -> INVOKING` under a PostgreSQL run lease, but the AppManager's package lifecycle changes live Features outside the write coordinator. A separate `planDisable` or read of pending receipts would race a just-admitted Owner invocation. Source audit of `agents/enterprise-agent/pa02b-postgres-coordination.ts`, `pa02b-owner-reconciliation.ts`, `manager/service.ts`.

**Bounded implementation:** Add an **explicit opt-in** `requirePluginWriteLifecycleFence` flag to the existing Postgres coordinator: before `beginWrite` transitions to INVOKING in the *same transaction*, it must find the **trusted persisted Owner link** for that effect and lock the Owner's `pa05_plugin_write_lifecycle_gates` row. If the gate is missing or FROZEN, refuse; never let an Agent invent the ownerPackageId. A separate Host-owned `createPa05PluginWriteLifecycleGateV010` port freezes that identical package row inside a transaction, then examines all linked PREPARED/INVOKING/UNKNOWN writes across scopes, using **counts only**, not leaking other tenants' Run identifiers. If WRITE began first, freeze reports a blocker; if freeze began first, WRITE cannot start. Both orders rely on durable SQL row locks, not memory or post-hoc checks.

**Draining:** `transition({operation:DISABLE|UNINSTALL|UPGRADE})` refuses while any linked operation remains nonterminal, regardless of whether the Owner committed. It never calls a hypothetical compensating WRITE. It retains FROZEN after successful manager mutation or exceptions; Owner verification must reconcile UNKNOWN before lifecycle transition. `reopen` requires active currently installed version, explicit trusted Owner re-certification and no outstanding linked nonterminal writes; it never silently adopts an upgraded version or re-opens after restart.

**Proof:** `tests/agent-line/pa05-plugin-write-lifecycle-fence-pg.test.mjs` exercises both transaction orderings, durable UNKNOWN, alternative tenant scope, disabled package/re-enable and version/Owner validation with a fresh isolated PostgreSQL18 schema. The focused WRITE CI must display `PA05_PLUGIN_WRITE_LIFECYCLE_PG` in addition to existing true PG Owner/Worker markers. Test execution / exact head must be checked before a PASS claim.

**Unresolved deployment and safety gates:** This opt-in port is **not connected to `manager/server.ts` or the global AppManager lifecycle entrypoints**. A Host that uses unguarded coordinator or calls `manager.disable/upgrade/uninstall` directly can bypass the pilot protection; multiple database schemas/Owner registries require authoritative global coordination. A Host-managed authority ensuring every governed writer and every lifecycle caller uses the same durable gate, trusted Owner version and identity source, complete prepare/link/orphan handling, actual upgrades/rollback/forced verifier outage, real sessions and production-like race tests remain required before closing Issue #913. Since AppManager state is separate from PostgreSQL, this is a durable **freeze across a nontransactional manager mutation**, not a falsely claimed single transaction covering both stores. PA05-W06 **NOT_SIGNED**, PA-05 **IN_PROGRESS / NOT_SIGNED** and production WRITE disabled.

## 13. PA05-04C Host package lifecycle entrypoint pilot (2026-10-15 candidate)

**Source observation:** `manager/server.ts` exposes **eight** mutating package lifecycle call sites: in two `app-platform.*-package` action handlers (upgrade, disable, uninstall) and `/v1/upgrade`, `/v1/disable`, `/v1/uninstall`. PR #915 guarded WRITE only at opt-in Postgres coordinator and Host lifecycle Port, but left these request handlers directly invoking the unguarded `AppManagerService`. That was an independently reachable bypass of the pilot where the Host did have a protected WRITE Owner.

**Bounded Host integration:** New `manager/agent-plugin-write-host-lifecycle.ts` is a Host-only adapter reused by all eight calls in `manager/server.ts`. It reads the following **trusted process configuration only**, never HTTP request fields: `PA05_WRITE_LIFECYCLE_PACKAGES` (exact protected package ID list), `PA05_WRITE_LIFECYCLE_DATABASE_URL`, and `PA05_WRITE_LIFECYCLE_SCHEMA`. All three are required for a protected owner; partial or duplicate configuration fails startup. Protected lifecycle transitions use the already-vetted `createPa05PluginWriteLifecycleGateV010` with the **same schema as the configured opt-in PA-02B coordinator**. A missing persisted gate, outage, absent owner, active/UNKNOWN WRITE or owner version mismatch **fails closed to HTTP 409**; no fallback to `manager.disable/upgrade/uninstall`. The original manager upgrade approval parameters are explicitly forwarded. Unprotected READ-only plugins keep their existing Host lifecycle behavior. The adapter retains the durable FROZEN state after success or interruption, does not issue Owner writes, and closes the database on shutdown.

**Verification scope:** `tests/agent-line/pa05-host-write-lifecycle.test.mjs` statically verifies all eight Host routes use the common seam (zero unguarded calls), validates trusted config, upgrade context, outage/unknown fail-closed, and an unaffected READ package. The expanded isolated PostgreSQL18 `pa05-plugin-write-lifecycle-fence-pg.test.mjs` calls the **actual Host adapter** over the production SQL lifecycle Port, proving linked PREPARED blocks disable and that eligible disable leaves FROZEN. `agent-pa05-governed-write.yml` includes both tests and requires `PA05_HOST_WRITE_LIFECYCLE_PG`; no skipped PG acceptance. Exact-head CI must be observed before marking an engineering PASS.

**Critical remaining limits:** The protected set is explicitly configured, not automatically all packages exposing `writeSafety`; unconfigured deployments retain old behavior. The Host currently still does **not** register a production material WRITE owner/coordinator, so pilot evidence is not live global safety. The Host and PA-02B coordinator must be configured together and all material-write Owner registrations validated; external management paths, actual upgrade+rollback race, multiple data schemas, forced verifier outage and credential-bound Human traffic are not signed.
