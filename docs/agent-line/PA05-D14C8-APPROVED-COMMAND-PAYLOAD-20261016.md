## Option and bounded implementation

**Adopt a Host-private expected snapshot on the same SQL permit row.** Reuse the **one** original Object Extension Owner material builder for its complete `resource`, original `evidence`, `evidence_digest` and `idempotency_hash`; move construction before the unchanged atomic Owner insert and before independent Host SQL permit issuance. The opt-in independent Host adapter recomputes canonical `SHA-256({definition: evidence.definition})`, the evidence digest and identity/record consistency before presenting the expected resource and receipt to the already-isolated SQL issuer. Host's `SECURITY DEFINER` issuer records this complete snapshot with its existing opaque permit, D10 ticket, PA-02 invoking, physical frozen gate and D14C6 credential role audit. No API allows Business SQL LOGIN to read or rewrite the expected snapshot.

**The existing physical PostgreSQL trigger enforces exact stored contents:** on `pa02_definitions` it compares actual `extension_id`, target type/slot/field, complete JSONB resource and created timestamp against Host-approved resource; on `pa02_owner_evidence` it compares original receipt ID, resource ID, idempotency hash, evidence digest, full JSONB evidence and timestamp against approved evidence. Context/tenant, run/effect/digest, revoked/consumed row lock, deferred receipt constraint and original independent Owner verifier remain the same. PostgreSQL JSONB equality is used for structured documents; timestamps use `timestamptz` equality. A row mismatch rolls back the original business transaction; no alternative Provider or second receipt engine.

**Rejected:** approving only `inputDigest` (not an integrity check of material DB rows), checking after commit in an optional JS layer (direct business SQL bypass) and a false claim that the bearer token proves the physical source process. This slice does not install any default production route.

## Explicitly NOT_SIGNED

- **Independent trusted-command provenance:** the opt-in Host adapter receives the approved snapshot from the existing Owner invocation path and checks consistency against D10 digest, **not against a separately authenticated immutable Host command database**. Compromise of the *Host SQL issuer credential*, an attacker able to submit a valid different command to it, or dual SQL credential theft are not solved. Canonical hash checks in the Host adapter are not independently enforced for a direct compromised Host SQL LOGIN.
- **Bearer replay of the *same approved contents* before legitimate Owner commit:** a stolen valid unrevoked permit and Business LOGIN may race to insert *identical* approved resource/evidence. This slice prevents **payload substitution**, not machine identity impersonation.
