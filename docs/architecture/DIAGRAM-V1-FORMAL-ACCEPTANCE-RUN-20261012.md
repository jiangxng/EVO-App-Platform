## 2. 正式验收规则与边界

- 单项必须达到完整 §14 **预期结果**，且有**实际交互证据**、使用环境与版本方可判为 `PASS`。`FAIL` 有复现步骤及截图/录像；`NOT TESTED` 表示未达到完整证据门槛。若只验到一部分，保持 `NOT TESTED`，在备注填 `PARTIAL`，不虚报通过。
- 每轮保存：日期时间、测试人（可使用非个人识别代号）、机器与 OS、浏览器版本、输入设备、页面 URL 路由（隐藏企业/业务 ID）、Enterprise Context（匿名）、图规模及结构、`GitHub commit / Railway server commit / browser asset revision`、操作步骤、观测结果、截图/录像或已有 CI URL。
- **生产数据安全**：第一轮仅做在当前编辑器**本地状态**中的可逆操作，明确**不点击「保存投影」**；返回或刷新可能丢弃未保存编辑。需要保存、并发或破坏性/失败注入场景（D01–D05），先使用隔离的验收投影/企业环境并取得明确确认；禁止在真实客户数据中故意制造 503、并发覆盖或丢数据。
- 用户辅助真实操作，2D 专项窗口负责路径、读代码、记录结果和分派**已证实的最小缺陷**；不接管 Agent/Ledger Runtime/TR-01，不直接操作 Railway 生产配置或数据。不因业务版本差距直接部署整站。
- 设备覆盖：Windows Chrome/Edge + 鼠标、Mac 触控板、iPhone/iPad Safari、Android Chrome；无法接触的设备记录 `NOT TESTED`。测试数据至少稀疏链路、S2C、P2P、密集交叉、并行边/回环、长文本、负坐标、锁定/隐藏、旧版无样式。
- 用户提供的截图留存在聊天中时，只能标注“当前聊天附件，**未上传 GitHub**”；获得具体持久来源后再填写正式证据 URL。不得引用不存在的附件或做推断。
- 启动状态不是正式 PASS。修复独立 2D bug 的代码提交与用户验收单独记录，不可将 CI 运行自动签收为人工 PASS。

**选择对象**：用户先前确认正常的 S2C「从销售到收款」投影编辑页面，使用画面中的 `Rule ID 108 · 开票 → 应收账款` 连接（或者另选一条方向清楚、不与其他边完全重叠的连接）。截图当时右侧显示 `Connector path (presentation only)`、`Straight`、`Source attachment = auto`、`Target attachment = auto`。这是历史截图观察，执行前须以当前页面为准。

**用户可执行、无保存操作**：
1. 进入同一投影编辑页面，选择该连接，确认业务源目标和 Rule ID。
2. 打开右侧 `Connector path (presentation only)`，依次选择 `Straight`、`Orthogonal`、`Rounded orthogonal`、`Curve`，每种状态观察（或截一张图）实际边路径与箭头位置。
3. 验证四种形态的差异、圆角折线与曲线不混同、业务方向/属性/两端节点未被变更。若出现确认框，仔细阅读，仅在预期清除**本地**手工控制点时确认。
4. **不点击保存投影**；用撤销或重新加载丢弃此次演示变更。为避免丢失此前未保存工作，应在无其他重要草稿时进行。

**PASS 门槛**：四种形态均成功展示且确实可区分；至少圆角折线和曲线不同；两端绑定/箭头业务语义不变；附执行环境和截图/简明视频及提交版本。仅从下拉选项**存在**不得判通过。

**执行结果**：`NOT TESTED`；等待用户操作后的截图/口头观察及必要设备信息，尚未宣称用户已完成本轮测试。首次已有的 S2C 正常截图只是选择测试对象的依据，不代表 V01 通过。
