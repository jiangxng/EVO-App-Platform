## 2. 正式验收规则与边界

- 单项必须达到完整 §14 **预期结果**，且有**实际交互证据**、使用环境与版本方可判为 `PASS`。`FAIL` 有复现步骤及截图/录像；`NOT TESTED` 表示未达到完整证据门槛。若只验到一部分，保持 `NOT TESTED`，在备注填 `PARTIAL`，不虚报通过。
- 每轮保存：日期时间、测试人（可使用非个人识别代号）、机器与 OS、浏览器版本、输入设备、页面 URL 路由（隐藏企业/业务 ID）、Enterprise Context（匿名）、图规模及结构、`GitHub commit / Railway server commit / browser asset revision`、操作步骤、观测结果、截图/录像或已有 CI URL。
- **生产数据安全**：第一轮仅做在当前编辑器**本地状态**中的可逆操作，明确**不点击「保存投影」**；返回或刷新可能丢弃未保存编辑。需要保存、并发或破坏性/失败注入场景（D01–D05），先使用隔离的验收投影/企业环境并取得明确确认；禁止在真实客户数据中故意制造 503、并发覆盖或丢数据。
- 用户辅助真实操作，2D 专项窗口负责路径、读代码、记录结果和分派**已证实的最小缺陷**；不接管 Agent/Ledger Runtime/TR-01，不直接操作 Railway 生产配置或数据。不因业务版本差距直接部署整站。
- 设备覆盖：Windows Chrome/Edge + 鼠标、Mac 触控板、iPhone/iPad Safari、Android Chrome；无法接触的设备记录 `NOT TESTED`。测试数据至少稀疏链路、S2C、P2P、密集交叉、并行边/回环、长文本、负坐标、锁定/隐藏、旧版无样式。
