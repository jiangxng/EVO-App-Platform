## 一、产品验收原则

- **目标是实际可用。** 用户自行操作并确认通过，即为开发阶段功能验收；不要求逐项截图、录屏、设备型号、签字或第二套「正式证据签收 0/39」，它不是当前 KPI。
- **不把功能冻结。** 以后想到新功能、发现不足或交互问题，继续改进；出现具体缺陷时再收集复现步骤、截图或日志并做针对性回归，不为形式重新验证其余 38 项。
- **自动化是辅助。** 39/39 个编号都有范围受限的浏览器自动化子场景，但不由此虚构真实多设备、实际生产场景、定量性能、故障注入或双实例覆盖细节。
- **用户验收与生产发布分开。** 用户报告功能可用不等于最新 GitHub main 已部署，也不保证所有环境插件权限一致；部署核对按实际需要另外进行。
- **数据安全不变。** 不在重要生产企业数据中故意制造保存失败、并发冲突或丢失数据；用户口头确认可以如实记录，却不虚构执行环境。
