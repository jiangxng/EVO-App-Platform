# EVO 2D Designer 商业化交互与视觉实施要求 v1.0

编制日期：2026-10-09（香港时间）  
用途：交给后续实施窗口的产品要求、交互规则和验收依据。  
状态：基于当前仓库与公开官方资料提出的实施建议；不是已经实现或已经上线的功能清单。

## 给实施者的首要说明：本轮是 2D Designer 整体体验升级

用户已明确：不满意的是当前 **2D Designer**，不要求泛化重做整个 Eidos，也不应等待用户逐项列举问题。实施者需要对编辑器的完整体验负责。

现有 Eidos 的品牌、公共契约和项目边界是约束；现有 2D Designer 的布局、能力不足和操作缺陷不是必须保留的设计。如果当前通用图形能力不足，应在 Eidos 的图形能力内补齐，再让产品使用。

推荐的成品定位是：**一个让业务人员看懂关系、快速整理投影的专业画布。** 学习 Miro 的导航手感、draw.io 的连线控制和成熟商务软件的安静界面，形成统一操作模型。

### 应有的完整使用过程

| 用户所处阶段 | 成品应该提供的体验 |
| --- | --- |
| 打开图 | 恢复保存视角；首次适应内容；图名称、查看/编辑模式明确；画布占主区域；没有空属性栏挤占宽度 |
| 看不清复杂关系 | 点击对象突出直接关联节点和边；其他内容温和弱化；搜索可以定位对象；可看关联关系列表 |
| 准备整理 | 明确进入编辑；选择工具为默认；可框选、批量移动、自动排版、改路径、隐藏不相关内容 |
| 精细调整 | 连线自动跟随；拥挤处可改折线、锚点或路径点；有对齐线、吸附和位置锁定；所有编辑可撤销 |
| 做错了 | Esc 取消当前动作；撤销恢复上一步；恢复隐藏和恢复自动布线都有直接入口 |
| 完成工作 | 保存当前投影，有明确成功或失败反馈；刷新、Viewer 和预览保持一致；不改业务数据 |
| 换到手机 | 可以清楚阅读、选择、调整和保存；控件与属性面板重新排布，手势适配触摸，数据含义一致 |

### 推荐默认值：无需让用户先做一轮配置

| 项目 | 推荐默认 |
| --- | --- |
| 新投影连线 | 圆角正交路径，自动路由；旧投影维持已有外观 |
| 节点 | 安静的圆角业务卡片，业务名称优先，类型辅助 |
| 图中颜色 | 中性色为主，品牌蓝用于选择，真实异常才使用警示色 |

| 桌面编辑 | 左键选择/框选/移节点，右键与空格拖动画布 |
| 触摸 | 先阅读，轻触选择后再移动；双指始终用于导航 |
| 属性区 | 选中才出现，批量选择显示共同属性，手机使用抽屉 |
| 排版 | 左到右，作用于当前可见投影，尊重锁定，结果可撤销 |
| 保存 | 展示编辑先本地完成，再保存当前投影；查看态不误写共享内容 |

### 整体质量要求

本方案不是增加一排按钮。实施窗口必须检查“打开、阅读、选择、移动、改线、撤销、保存、重新打开”这条完整链路。任何一步不清晰或不可靠，都不能因为已支持四种连线就宣称升级完成。

不把现有 Eidos 规范当作保留缺陷的理由；需要演进规范时，给出明确的通用能力改进，并在 Eidos 的既有体系内落地。

以下章节给出具体的可实现要求与验收标准。

## 1. 推荐方案与目标

把 2D Designer 做成清晰、稳定、容易操作的商务图形工作区。默认采用“圆角节点 + 圆角正交连线 + 左键选择/框选 + 右键拖动画布”，支持直线、直角折线和曲线。鼠标、触控板、触摸屏共享相同业务含义，但采用适合各自设备的操作方式。

商业化质量首先来自可预测的操作、清晰的关系、可靠的保存与恢复。图形美观必须和这些能力一起交付。

以下所有阈值、尺寸、默认值与阶段安排，除明确引用 eidos 现有规范外，均为本项目建议值，不宣称是所有软件统一采用的行业标准。实施窗口可依据实际测量微调，但必须记录调整理由并保持交互一致。

本轮任务范围：

- 改善既有 2D Designer，并让 2D Viewer 使用相同的图形和连线渲染能力。
- 完成鼠标、触控板、手机、平板的基本操作闭环。
- 新增可保存的连线路径与样式、批量选择、撤销重做等通用能力。
- 保留投影编辑与业务编辑的边界。
- 本文不要求更换渲染框架，不要求新增绘图引擎，也不要求引入收费组件。

### 2.3 必须遵守的归属

- Eidos 负责通用图形交互、渲染、样式令牌、图标、响应式和无障碍能力。
- App Platform / 对应插件负责业务词汇、可用动作、权限、投影身份、保存和业务关系的真实性。
- 不在插件中另造 CSS 体系、鼠标交互框架或手机外壳。
- 桌面、手机可以使用不同的组件树或渲染实现，但共享语义契约和数据模型，仍由 Eidos 管理。
- 优先组合已有能力。新增通用能力先在 Eidos 落地，再通过现有集成流程供项目消费。

## 4. 页面结构与工作模式

### 4.1 工作区结构

画布占据主要任务空间，不把大图塞进一个高度很小的表单卡片。

| 区域 | 内容与要求 |
| --- | --- |
| 顶部上下文 | 深层页面保留当前投影和父级路径；手机折叠为最近父级返回入口 |
| 页面操作栏 | 当前图名称、保存状态、撤销/重做、保存、更多；保存是编辑态主要动作 |
| 画布工具组 | 选择、手形、自动排版、对齐/分布；连线工具仅在业务允许建关系时出现 |
| 画布视图组 | 缩放百分比、加减、适应全部、适应选中、100%；与业务保存动作分开 |
| 上下文属性区 | 选中节点/边才显示；多选显示共同属性与选中数量；无选择时不永久占宽度 |
| 小地图 | 大图可开启，默认安静或折叠；手机不永久占据画布 |
| 帮助 | 提供“操作帮助”和当前设备模式入口，不能要求用户记住全部快捷键 |

悬浮控件不能挡住当前拖动目标、端点或主要内容；移动端控件须避开系统安全区与宿主底部导航。

### 4.2 三种权限与模式必须分清

| 模式 | 可以做什么 | 不可以做什么 |
| --- | --- | --- |
| 查看 | 选择检查、搜索、缩放、平移、临时阅读聚焦 | 改位置、样式、关系和保存共享投影 |
| 编辑投影 | 调位置、改展示样式、调整现有边路径、隐藏/恢复、自动排版、保存投影 | 新增或删除业务对象、改变 source/target、反转真实业务方向 |
| 业务图编辑 | 仅执行 Host 明确声明、当前用户获准的业务动作 | 不能由画布自行推断或绕过业务授权 |

“删除键”在投影编辑中应显示并执行“从当前投影隐藏/移除”，同时隐藏该节点连接的边，不删除真实业务数据。

投影保存仍更新当前投影，不因为换线型、移动节点产生新的账本定义版本；“另存投影”是显式创建另一投影。存储并发校验的修订标记不能被误解释为新增业务版本。

## 5. 节点与整体视觉

### 5.1 视觉基线

沿用 Eidos Business Office：中性色画布、白色业务表面、克制的品牌蓝、轻边框和浅阴影。字体、间距、圆角和图标均使用 Eidos 令牌。

当前令牌示例：画布 `#F5F7FA`、表面 `#FFFFFF`、正文 `#1F2933`、品牌蓝 `#2B6CB0`、选中浅色 `#EAF2FB`。这些是核对时的项目值，实施时引用令牌，不能把本段颜色复制成插件私有常量。

状态色只用于真实状态。节点类别可以使用受控的低饱和色，但必须配合类型文字或图标；不能以“采购是绿色、销售是红色”替代清晰语义。

### 5.2 节点形状和内容

- 默认圆角矩形；保留矩形。当前业务节点优先采用卡片式表现，避免无必要地增加十几种形状。
- 菱形仅用于已声明的判断/分支语义；圆形、圆柱等也需有明确类型含义。不可为了装饰把账本画成判断条件。
- 节点标题为主，类型为辅；技术 ID 放详情。标题可换行，建议最多两行并提供完整查看入口。
- 不改变节点业务名称以适配版面。超长名称通过布局和完整详情解决。
- 初始建议尺寸为 176×72 世界坐标单位，允许随内容增高；这是新布局建议，不强制改写既有尺寸。
- 100% 视图下标题参考 Eidos 正文字号，类型参考辅助字号；界面文字遵守 rem 与系统字体缩放。
- 暂不把自由缩放节点作为首批必需操作；若开放尺寸调整，须有最小尺寸、文本重排、连线锚点重算和保存支持。
- 小比例尺时隐藏辅助信息；极小比例尺允许简化为轮廓和类型标记，选中后仍可在属性区读完整信息。

### 5.3 必须可区分的状态

| 状态 | 表现 |
| --- | --- |
| 普通 | 中性边框与安静表面 |
| 悬停 | 轻微强调，不能与选中一样强 |
| 选中 | 品牌色边框/外环；不改变节点尺寸、不挤动布局 |
| 键盘焦点 | 独立且可见的焦点标记，可与选中并存 |
| 多选 | 每个选中对象有标记，群组有边界和数量 |
| 锁定位置 | 明确锁定标记；可检查但不能移动 |
| 不可编辑 | 解释原因，不用“变灰”代替权限说明 |
| 错误/警告 | 图标和文字同时表达，不覆盖选中状态含义 |

默认只在悬停、选中或相关编辑模式下显示连接锚点与路径控制点。不要让所有节点永久挂满小圆点。

## 6. 连线样式与布线

### 6.1 用户看到四种路径预设

| 中文名称 | 表现 | 适用场景 | 要求 |
| --- | --- | --- | --- |
| 直线 | 两端之间一段直线 | 稀疏关系图、紧邻节点 | 无手工折点；不能伪称自动避障 |
| 直角折线 | 水平/垂直线段，以直角转弯 | 规整流程、严谨路径 | 每段保持水平或垂直 |
| 圆角折线 | 正交路径，转角平滑圆化 | 默认商务流程、运行图 | 建议作为新投影默认 |
| 曲线 | 平滑贝塞尔式路径 | 跨层关系、回路、多条并行关系 | 控制点不穿进源/目标节点；标签跟随真实曲线 |

“圆角折线”与“曲线”必须视觉和数据语义都能区分。前者是正交路由加圆角，后者是连续曲线路径。圆角半径受相邻线段长度限制，短线段不可形成自交或倒钩。

既有投影如果没有新字段，应按旧版直线效果打开，不能升级后突然全变折线。用户可明确执行“应用推荐样式”改变当前投影。

### 6.2 分开管理各个维度

路径类型、线条纹理、箭头、颜色、宽度、标签和锚点互相独立：

- 纹理：实线、虚线；点线可后续扩展。
- 箭头：无、起点、终点、两端，是否可改由 Host 声明。
- 颜色：默认中性；用户高亮使用受控展示色；真实状态颜色由业务提供。
- 宽度：建议普通约 1.5 屏幕像素、悬停约 2、选中约 2.5；通过 Eidos 图形令牌管理。
- 如果箭头、虚线或颜色已经表达业务含义，对应字段应只读；不能让自由样式编辑伪造关系方向或状态。
- 不能通过选择“反转箭头”暗中交换 source/target；改变真实方向属于业务操作。

宽度、箭头和交互热区在缩放后仍须可辨认。不要只固定线宽而让箭头放大十倍，也不要让命中热区缩小到无法点选。

### 6.3 自动路由要求

- 自动路由优先保持已有路径稳定，再减少转折、绕行和交叉；不能每次轻微移动都让全图跳线。
- 正交线从合理边缘离开和进入节点，不能从节点中心穿过文字。
- 默认按主方向选择锚点，例如从左到右布局优先右出左入；反向和回路可走外侧通道。
- 区分“画一条折线”和“避开其他节点”：普通 L/Z 形连接不等于避障。专业阶段必须验证中间障碍场景。
- 圆角/直角自动路由应避开无关节点主体，建议障碍外留 12–16 世界单位间距；近距离和拥挤场景需可解释地降级。
- 两节点间多条边分别偏移，且排序稳定；反向边不得完全覆盖正向边。
- 自环（如果业务允许）必须走节点外侧，端点和箭头可见；业务不允许自环时不能自行生成。
- 交叉不代表相连，不得在交叉处自动添加节点或改变拓扑。跳线显示可选，不作为首批交付前提。
- 无法避障时保留数据，明确提示路径拥挤并允许人工调整；不能静默隐藏边，也不能让渲染崩溃。
- 移动无关节点形成新障碍时，在结束拖动后重新评估受影响的自动路径。

### 6.4 连接锚点

提供“自动锚点”和“固定边缘锚点”。自动锚点随布局选择合适边；手动固定后保持在指定节点边缘。

当前投影编辑只允许改变同一 source/target 节点上的展示锚点，不能把端点拖到另一个业务节点上。

如果未来进入有授权的业务连线模式，才可以提供拖拽建边、点击起点再点击终点、重接端点；必须实时显示合法目标与失败理由。建边取消不得留下悬空业务边。

### 6.5 手工路径

- 选中边后才显示折点/控制柄，不在全图常显。
- 拖动正交线段时，平行移动该段；相邻段自动修复，避免产生斜线和重复零长段。
- 提供“添加路径点”“删除路径点”“恢复自动布线”。不能只靠双击某个隐蔽位置。
- 路径点支持坐标或可点击微调方式，触摸设备不必精确拖住小点。
- 编辑路径不改变关系身份、源节点和目标节点。
- 两端节点同时等量移动时，手工路径整体平移；只移动一个端点时，尽量保持内部路径点，修复靠近该端的线段。
- 手工路径默认尊重用户位置；若压住节点则提示，不擅自全面重排。
- 从折线/曲线切换到直线时，明确说明手工路径将被重置，并可一步撤销。不能静默丢失控制点。
- 拖动结束才形成一次撤销记录；拖动过程不能产生数百条历史。

### 6.6 标签与选中效果

- 边标签按实际路径长度定位，不能继续用源/目标中心点的算术中点。
- 标签默认水平可读，避开箭头、转角和节点；底色或描边与画布一致，保持可读性。
- 密集图默认只展示选中/直接关联边的标签；提供“自动 / 全部 / 仅选中 / 隐藏”显示选项。
- 临时展开标签和邻域高亮属于阅读状态，不改投影可见性。
- 点击标签等同选择该边，拖动标签只在明确标签编辑模式中移动标签。
- 鼠标边命中宽度建议 12–18 CSS 像素，与视觉线宽分离；触摸边选择要配套至少 44px 的可点选关系列表或消歧菜单，不靠叠满的超宽透明线解决。
- 热区必须沿真实折线或曲线路径，而不是沿两个端点的直线。
- 重叠边无法直接点准时，提供候选关系菜单或“关联关系列表”。

## 7. 桌面鼠标操作规范

默认工具为“选择”。“手形”是明确的另一工具，按钮必须显示当前状态。

| 输入与位置 | 行为 |
| --- | --- |
| 左键单击节点/边 | 单选并显示属性 |
| 左键单击空白 | 清除选择，关闭与选择绑定的临时属性内容 |
| Shift + 单击对象 | 加入/移出选择集；不需要用户按住多个修饰键 |
| 左键拖动未选中节点 | 超过阈值后选中并移动该节点 |
| 左键拖动已选中节点 | 移动当前选择中的可移动节点，保持相对位置 |
| 左键拖动空白 | 在选择工具中框选；在手形工具中平移 |
| 左键从边上开始拖动 | 不移动整条业务关系；只有显式路径控制柄可调整路径 |
| Shift + 空白拖动 | 追加框选，已有选择不被清除 |
| 右键拖动画布/节点/边 | 平移视角；不移动节点、不改变选择、不弹出菜单 |
| 右键按下后原地释放 | 打开上下文菜单；已有选中对象上保留多选，未选中对象上切为该对象上下文 |
| 中键拖动 | 平移；避免触发浏览器中键自动滚屏 |
| 按住 Space + 左键拖动 | 临时手形，松开恢复之前工具 |
| 鼠标滚轮 | 鼠标模式下围绕指针缩放 |
| 双击节点 | 查看详情；仅业务明确允许时进入文字编辑；不得隐式放大 |
| 双击空白 | 首版不绑定自动建节点或缩放，避免误触 |

### 7.1 右键与拖动判定

- 鼠标移动建议达到 4 CSS 像素才算拖动，阈值不随画布比例尺变化。
- 右键在阈值内释放是菜单，超过阈值是平移，两者只能发生一个。
- 右键拖动结束不能落下一个 click 导致节点选中变化。
- 在节点上右键按下时，不得进入左键节点移动路径；必须检查实际按键。
- 只在画布内部且应用接管事件时阻止浏览器菜单；输入框、宿主导航、链接保留正常行为。
- 支持不同浏览器 contextmenu 触发时序，不能在右键按下瞬间就打开应用菜单。
- Space 在文本框、下拉菜单、对话框和输入法组合输入中不切换手形。
- 一次手势开始时确定工具与语义，拖动中释放 Shift/Space 不可突然把平移变为移动节点。

### 7.2 框选与群组移动

- 首版统一采用“与矩形相交即选中”的规则，不按左右拖动方向暗中改变规则。
- 默认框选节点，避免密集图一次框选顺便选择大量关系；边通过点击、Shift 点击或关系列表选择。
- 隐藏对象不参与选择；锁定对象可检查但不移动；批量动作明确显示跳过的锁定数量。
- 拖动矩形有轻品牌色填充和清晰边框，并实时显示待选对象。
- 群组移动使用同一位移量，不能对每个节点独立吸附造成队形变形。
- 指针接近画布边缘时可缓慢自动平移；只有正在拖动/框选时启用，结束和取消立即停止。
- 选择本身不改变保存状态，不生成业务操作。

## 8. 触控板、手机和平板

### 8.1 触控板

提供“鼠标 / 触控板”导航偏好，允许自动建议，但不能只凭一次 wheel 事件永久判断设备。浏览器常不能可靠区分所有鼠标与触控板，必须有手动覆盖并记住用户选择。

| 输入 | 触控板模式行为 |
| --- | --- |
| 双指滑动 | 平移，可同时水平和垂直 |
| 双指捏合 | 围绕手势锚点缩放 |
| 按下触控板并拖空白 | 选择工具中框选 |
| 按下并拖节点 | 移动选中节点或群组 |
| 二指轻点/系统右键操作 | 上下文菜单 |
| 画布获得焦点后的 Ctrl + 滚轮 | 作为画布缩放替代；macOS 按平台实测适配并在帮助中显示 |

处理 wheel 的连续数值、deltaMode 和惯性，不可每个事件固定跳 12%，也不可把捏合同时处理成平移和浏览器页面缩放。画布外仍保留浏览器滚动与缩放。

### 8.2 触摸屏的明确规则

触摸按实际 pointerType 判定，不按屏幕宽度简单判定。平板接鼠标、触屏电脑、手机接触控板都应按实际输入操作。

| 手势或按钮 | 行为 |
| --- | --- |
| 轻触节点/边 | 选择并展示上下文操作；边密集时提供候选列表 |
| 轻触空白 | 清除选择；不能触发保存或跳页 |
| 单指从空白拖动 | 默认平移画布 |
| 单指从未选节点拖动 | 浏览模式中平移，不立刻移动节点；轻触完成后才能选中 |
| 单指拖动已选节点 | 编辑模式下超过阈值后移动；查看模式下仍平移 |
| 双指拖动任意画布位置 | 平移，不移动对象 |
| 双指捏合 | 缩放；允许同时平移，手势中心保持稳定 |
| “多选”按钮后逐个轻触 | 加入/移出选择集 |
| “框选”工具后单指拖动 | 绘制选择矩形；结束后回到普通触摸导航，可再次点击工具继续 |
| “移动”操作 | 进入明确的节点移动操作，并提供方向微调按钮 |
| “更多”按钮 | 打开对象菜单；长按不是唯一入口 |

触摸移动阈值建议 8 CSS 像素。长按可作为上下文菜单快捷方式（建议约 500ms），但与平移、拖动、文本选择必须消歧；不使用同一长按同时做菜单和框选。

### 8.3 多指中途加入、取消与恢复

当第二根手指加入正在进行的节点拖动/框选：

1. 取消尚未提交的节点移动或框选，恢复该手势开始前状态。
2. 从当前双指位置建立缩放/平移基准，画布不得跳变。
3. 缩放后剩一根手指，允许继续平移，但这次手势结束前不得自动恢复节点拖动。
4. pointercancel、失去捕获、窗口失焦或组件卸载时，未完成编辑回滚；导航停在最后有效相机位置。

这些是必须通过的行为测试，不接受“通常能用”。

### 8.4 手机界面要求

- 手机仍以画布为主，属性用底部抽屉/覆盖层，不能常驻左右两栏。
- 手机可使用独立排布的工具条；所有普通交互按钮至少 44×44 CSS 像素。
- 保留查看、选择、移动、线型切换、撤销重做、保存等核心操作；精细路径点也应可用面板数值/按钮调整。
- 不靠横向滚动一长排小图标寻找命令。常用动作可见，次要动作进入更多。
- 顶部清楚说明当前是查看还是编辑；保存时保持反馈可见。
- 软键盘、横竖屏、抽屉开合后保留选择和视角，不随意 fit 全图。
- 画布可以接管自身手势；面板、表单和页面其他区域必须正常滚动。不能全页面禁用触摸或浏览器辅助放大。

## 9. 快捷键、焦点与非手势替代

以下只在画布拥有操作焦点且无文本编辑/模态操作时生效。优先保留 Eidos 已有约定。

| 快捷键 | 行为 |
| --- | --- |
| V / H | 选择 / 手形工具 |
| Space 按住 | 临时手形 |
| Esc | 先取消当前拖动/框选，再关闭临时菜单，最后清除选择；一次只处理最内层状态 |
| Ctrl/Cmd + A | 选择当前投影可见节点；不选隐藏数据，不劫持输入框全选 |
| Ctrl/Cmd + Z | 撤销一次本地展示编辑 |
| Ctrl/Cmd + Shift + Z | 重做；Windows 可兼容 Ctrl + Y |
| Delete / Backspace | 投影中隐藏已选项；无权限时不执行业务删除 |
| 方向键 / Shift + 方向键 | 已选可移动节点移动 1 / 10 世界单位 |
| + / - | 缩放画布 |
| Shift + 1 / Shift + 2 | 适应全部可见内容 / 适应选择 |
| Ctrl/Cmd + 0 | 画布 100%；只在画布操作上下文接管，其他区域保持浏览器行为 |
| Ctrl/Cmd + S | 有保存权限且在编辑状态时保存当前投影 |

不默认新增复制、粘贴和重复节点快捷键，因为投影复制不等于业务对象复制。需要此能力时单独声明安全语义。

无障碍与替代操作：

- 节点和关系列表可搜索、可选中，支持键盘导航和定位到画布。
- 移动可通过方向按钮或位置输入完成；视角平移可通过导航按钮完成。
- 路径点可在列表中增删和调整；框选可用多选列表替代。
- 缩放有加减和比例输入，不能仅支持滚轮/捏合。
- 图标必须有可访问名称，桌面有 tooltip，移动端关键动作有短标签。
- 面板/菜单关闭后恢复到原对象或调用按钮，不能把焦点丢到页面顶部。
- 批量选择、保存成功/失败用适度状态播报；不要在每帧拖动时连续播报。
- 页面放大、系统大字、减少动态效果设置下仍可操作；不能只凭画布截图宣称符合无障碍标准。

## 10. 自动排版、吸附与手工编辑的关系

- “自动排版”保持固定功能，无需 Agent 才能调用。
- 排版范围明确为“当前投影可见内容”，不得把隐藏节点重新引入。
- 默认方向左到右，可切换上到下；已有方向偏好优先。
- 排版是本地可撤销操作，执行后提示“已调整，尚未保存”。
- 锁定位置的节点不移动，算法在其周围安排其他对象；若暂时不支持固定约束，应明确阻止冲突排版并说明，不可悄悄解锁。
- 自动路径随新位置重算；对手工路径提供明确选项。建议当图中有手工路径时提示“保留手工路径 / 重新布线”，并允许撤销整次排版。
- 排版不改变关系方向、边类别、节点类型或业务名称。
- 提供网格显示、网格吸附、对齐参考线，三者独立；默认采用轻网格和温和参考线，不让网格抢眼。
- 吸附距离建议约 6 屏幕像素，受缩放换算；显示参考线时用户能理解为何停在那里。
- 支持水平/垂直对齐、等距分布；对象数量不足时禁用并给出理由。
- 排版后不强行覆盖用户保存视角；首次无相机时 fit 全图。执行排版可平滑适应新范围，但需尊重减少动态效果偏好。

## 11. 保存、撤销、兼容与数据约束

### 11.1 保存闭环

本轮新增的任何可编辑项，都必须经过“编辑 → 保存 → 刷新 → 查看器打开”完整往返。不接受刷新丢失样式。

需要覆盖的展示数据至少包括：

- 节点位置；如果允许编辑，还包括尺寸与展示样式。
- 图级默认路径和样式、逐边覆盖值。
- 边路径类型、路由模式、路径点或曲线控制数据、固定锚点、标签位置。
- 展示允许范围内的纹理、宽度、颜色；业务锁定字段不得被覆盖。
- 隐藏节点/边、保存的相机状态、位置锁定状态（若开放）。

选择、悬停、打开哪个面板、设备操作偏好属于交互/个人状态，不能误写成共享业务数据。鼠标/触控板偏好与图形内容分开保存。

### 11.2 撤销与重做

- 一次拖动、一次批量样式修改、一次隐藏、一次排版，各计为一步。
- 至少保留本编辑会话最近 50 步展示操作；这是实现目标，不要求首版跨刷新恢复历史。
- 选择、临时高亮和普通视角平移缩放不进入内容撤销栈。
- 保存成功后建立新的已保存基线；继续撤销可以回到旧展示状态，并重新标记为未保存。
- 新编辑清空已分叉的重做分支；不能跨到另一投影撤销。
- 业务动作若不可逆，不得伪装为普通本地撤销；本轮主要保证投影展示操作。

### 11.3 未保存与失败恢复

- 位置、样式、隐藏、路径修改后显示未保存；保存成功后清除。
- 只有相机变化时不强制弹离开确认；按项目策略记作视角状态，并在显式保存时一起捕获。
- 保存过程中禁止重复提交；编辑可继续时须用快照/修订机制避免把后续改动误标记为已保存。
- 保存失败保留全部本地修改，可重试，不回退为空白或旧图。
- 离开有内容修改的投影时提供保存/放弃/继续编辑选择；不得只依赖浏览器 beforeunload。
- 两窗口同时保存须检测过期状态，提供重新加载或保留本地修改的恢复路径，不静默覆盖他人的新内容。
- Agent 更新当前投影时走同一验证与状态机制，不直接替换掉未保存的本地编辑。冲突时展示差异或明确选择。

### 11.4 兼容性和校验

- 扩展公开契约需明确版本与向后兼容规则；不能随意重定义已有 style 字段。
- 缺少新字段使用旧行为；未知新枚举不能悄悄被旧端忽略后覆盖保存。
- 所有坐标、尺寸、线宽、缩放与控制点验证有限数值、范围和数量上限。
- 端点引用必须有效；不允许由输入路径数据改变关系身份。
- 控制点数量、标签长度和图规模要有保护，避免异常数据拖死页面。
- 只接收声明式数据，不把任意 SVG、CSS 或脚本作为样式契约。
- 投影编辑、企业运行图编辑、模板预览、2D Viewer 和现有缩略图链路均需核对；已支持导出的路径也需保留样式。不得出现“编辑器正确，预览重新变直线”。
- 保留负坐标与无限画布能力，不能在路由或持久化时把负数裁成 0。

## 12. 交互实现质量和性能要求

实施可自主选择技术方案，但必须满足以下结果，不把底层库默认行为当产品规范：

- 同一时刻只有一个主手势：空闲、按下待判定、节点拖动、框选、平移、捏合、路径编辑、文字编辑等互斥。
- 拖动提交与取消分开处理，pointercancel 不得当作 pointerup 提交位置。
- 持有指针时离开画布仍能正确结束；窗口失焦、组件销毁清理监听器和自动平移。
- 不在每次 pointermove 重建全画布 DOM；移动节点时只更新必要节点与相邻边。
- 现有代码在节点拖动时先移动节点元素，连线在重绘后更新；本轮必须让边与箭头在拖动中实时跟随。
- 相机变换期间节点与边共用同一坐标系统，缩放后拖动距离不翻倍、框选位置不偏移。
- 所有实例的 SVG marker/clip 等 ID 具有实例隔离；同一 Workbench 多开两个图不串箭头样式。
- 高成本避障可在拖动时做轻量预览，松手后精算；过程连线不得脱离端点。
- 路由异步计算必须丢弃过期结果，不能用旧计算覆盖较新的节点位置。
- 缩小视图时降低标签/细节密度；确有需要再引入裁剪与空间索引，不为微小图过度设计。

性能预算为待测目标，不能在未测试时宣称达到：

| 场景 | 测试规模与目标 |
| --- | --- |
| 桌面常用图 | 200 节点、400 边；常规拖动/平移目标接近 60fps，主要交互反馈在 100ms 内 |
| 桌面压力图 | 500 节点、1000 边；持续操作不冻结，目标至少 30fps，长计算有反馈 |
| 手机常用图 | 100 节点、200 边；目标至少 30fps，选中、平移、捏合不互相误触 |
| 保存与路由 | 耗时操作不阻塞输入；超过约 300ms 给出处理中状态，失败可恢复 |

记录设备、浏览器、图规模和测量方法。若现有产品实际图规模更大，以真实场景增加样例，不能只用 5 个节点截图验收。

## 13. 分阶段实施与交付边界

本要求的完整交付包含 A、B 两阶段；C 是明确可延期项。不得只完成 A 就称“商业化交互全部完成”。每阶段都要能独立验证与回滚。

| 阶段 | 必须交付 |
| --- | --- |
| A：基本闭环 | 四种路径渲染、Eidos 视觉统一、样式面板、鼠标左右键分工、框选/多选、群组移动、触控板与双指导航、基本撤销重做、完整保存/查看器往返、权限边界 |
| B：专业编辑 | 障碍避让、稳定并行边/回路、手工路径点/锚点、路径重置、吸附对齐、手机精细操作替代、取消/冲突恢复、性能与完整设备验收 |
| C：后续增强 | 跳线、复杂边捆绑、完整泳道/分组、更多业务形状、触控笔专门模式、可自定义快捷键、更多导出格式 |

若 A 阶段已有折线但尚不避障，应在交付说明中明确“折线路径已支持，自动避障待 B”，不能把演示效果当完整布线能力。

## 15. 给实施窗口的执行要求

1. 先读当前 Eidos 设计权威与两仓库最新代码，输出简短的“已有/待补/受其他窗口影响”清单。
2. 确认本任务使用哪些分支、是否与其他窗口触及相同文件。使用独立分支/PR，不覆盖已有未提交改动。
3. 把本要求纳入现有项目文档体系；通用交互规范归 Eidos，产品投影规则归插件/Host。
4. 先扩展契约和状态模型，再实现交互。避免在单个大文件不断追加互相竞争的 pointer 监听器。
5. 沿现有 Eidos 集成机制更新下游，逐项保留 vendor 与上游之间有效差异，不能整目录盲目覆盖。
6. A、B 阶段分别交付可验证结果。自动化覆盖状态转换、路径几何、持久化往返和权限边界；浏览器验证真实按键/手势。
7. 不因为参考 React Flow 就擅自改成 React，不因为参考 draw.io 就完整嵌入另一个编辑器。若现有实现确需引入图形/路由库，先明确许可证、体积、可替换边界和收益，再记录选择。
8. 不改变主线业务逻辑、账本定义版本策略或其他窗口负责的页面。全局项目状态按既有所有权规则更新。
9. 提交时说明：完成哪些产品能力、哪些待验证、如何在线验收；区分已提交、已合并、已部署、已人工验证。
10. 向用户只汇报项目进度和体验变化，技术细节写入项目文档与 PR；本交接文档本身不构成发布或合并授权。
