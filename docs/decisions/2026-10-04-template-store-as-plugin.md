# Decision Record — Template Store as an Independent Plugin

**Document class:** DECISION_RECORD  
**Status:** Accepted  
**Date:** 2026-10-04

## Context

Template sharing needs a product surface where enterprises can discover reusable definitions created with tools such as the 2D Designer.

A potential architecture ambiguity was whether Template Store should live inside Enterprise Context because the shared content ultimately originates from enterprise definitions.

That would couple an optional sharing/discovery surface to the enterprise definition authority and make Enterprise Context responsible for marketplace-style presentation concerns.

## Decision

Template Store is an independent EVO App Platform **APPLICATION Plugin**.

The boundary is:

```text
2D Designer -> Submit -> Enterprise Context -> Share -> Template Store

Template Store -> Copy -> Enterprise Context
```

Enterprise Context remains authoritative for enterprise definitions and the decision to share.

Template Store owns browsing/shared-content presentation and later the copy initiation workflow.

Template use is copy-based, not reference-based: after copy, the target enterprise owns an independent copy and does not retain a required runtime dependency on the source Template Store entry.

## Consequences

- Template Store can evolve, be disabled or be replaced without breaking Enterprise Context.
- Enterprise Context does not need Template Store to define or run an enterprise.
- 2D Designer does not publish directly to Template Store.
- Submit remains distinct from Publish and Share.
- Shared template thumbnails can be generated by 2D Designer Submit but are rendered through reusable Eidos capabilities.
- The first implementation can begin as a browse-only plugin and add governed Share/Copy contracts incrementally.
- Future synchronization/upgrade semantics are not assumed and require a separate decision.
