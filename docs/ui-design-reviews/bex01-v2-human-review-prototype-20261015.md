# BEX-01 / CP-03 V2 模拟 Human UI 原型设计必检记录（2026-10-15）

**适用变更：** `docs/plans/foundation-list-experience/BEX-01-IMPORT-V2-HUMAN-REVIEW-PROTOTYPE-20261015.html`。仅研究用静态 HTML，作为设计决策与浏览器验收前的交互草稿，**不涉及真实 EVO 页面、Host API、原始 Excel 数据或正式部署**。上游权威为 Eidos Human Experience Design Authority v1.0、Human UI Design Review Checklist v1.0、Navigation/IA、Productive Design Language、Business Office Visual Language v0.2、Visual Cognitive Reference Index。附属业务研究在 BEX §7–8，研究状态严格沿用原交接，外部原文未在本次重复打开。

## 目标与完成条件

操作者是获得企业授权的供应商数据导入业务人员。Human 目标是从 Excel 安全导入供应商，尽可能少重复映射和跨页记忆；可看见文件、已恢复的决定、真正的歧义与下一步；不确认的字段绝不能成为正式 Schema 或业务数据。本次 PR 的完成条件**仅为模拟原型能清晰展示这一设计意图和缺口**。真实完成仍须原 XLSX 与 `import-33ff3446-80c5-4992-b5c6-710f415535b3` 的授权实测。

## 流程与步骤

采用用户感知“上传 → 核对并导入”两阶段。当前原型**只展示第二阶段**，基于 7 条明确标记的假数据：文件与分析摘要 → 需要 Human 判别的开户银行 / 主体类型异常 → 若选择批量新建则一次确认完整字段清单 → 预检查阻断或成功模拟 → **另一次**明确最终导入模拟。原型不跳 7 个单列新建页面，不暗自根据供应商关系填主体类型。两次不同副作用的授权边界不因为两阶段命名而被合并。

## 导航与信息架构

原型不添加系统主导航或 Settings。业务入口属于当前供应商导入任务上下文，技术路径和 UUID 不在主视觉；保留简洁位置说明，未来 Host 需提供真正的返回/任务恢复入口。文案“供应商管理 / 导入供应商”在演示中明确不是可点击链接，真实实现需要导航行为而不是假链接。

## 视觉与颜色

内容按一级任务标题 → 文件和保存状态 → 状态摘要 → 必须决定的例外 → 完整来源列展开 → 唯一主动作排序。静态 CSS 仅为演示参照而非新视觉权威；正式实现必须继承 Eidos 既有 tokens、组件、字体、按钮与表格，不复制本原型的硬编码调色板。预检不通过时“重新预检查”为高权重动作、正式提交不可用；预检成功后提交为唯一主动作，重新检查降为次要操作。参考范围分别为 Productive Design Language 和 Business Office Visual Language v0.2。

## 记忆与注意力

历史映射优先级仍为当前工作决定 → 同企业合法 Recipe/历史 Human 映射 → 规则 → AI 剩余建议；无法访问的真实字段都不能在原型里伪称已恢复。保存状态显著标明“浏览器内模拟状态，非 Host”，支持刷新演示、回退修改和不重复审批未更改的 Schema 提案；但来源数据、持久化、并发冲突、有效版本与失败重试必须在实际 Host 实现。真正每列原始值要授权保留，完整明细可按需展开；默认 22 大下拉不回归。

## 无障碍与跨年龄

原型有表格列标题、输入标签、明显键盘焦点、展开状态 `aria-expanded`、关联区域 `aria-controls`、状态提示 `aria-live` 和预设 44px 按钮高度；正常和窄屏以重排而非缩小文字为目标。已做静态标签/ID/关联检查；**随后增加了 Chromium 自动浏览器证据，但尚无屏幕阅读器和 Human 签收**。真实系统仍需 200%/400% 放大、键盘、对比度文本 4.5:1/非文字 3:1 与触控目标量测。不同年龄使用同一可读界面，不据年龄减权限或自动简化功能。

## 安全与数据修复

当前原型不发网络请求、不访问导入作业、不创建真实扩展字段、不修改供应商，演示字段 DEMO-A/B 不代表真实银行字段。真实项目必须满足 Owner 认证、字段 Schema 创建前明确确认、一对一不重复占用目标、排他后端校验、原值留存、旧 dry-run 随修改失效、预检查通过且权限有效后最终显式提交。部分成功时必须支持幂等重试；历史两条“开户银行”不可合并删除；三条缺失主体类型只能依据实际身份合法修复并审计，不能拿演示选择当用户数据。

## 证据与剩余问题

在 GitHub 上核查新增 HTML 原文及其 29 个元素 ID：未发现重复，输入标签、展开的 aria-controls、静态 JS ID 引用均对应有效元素；源文件没有 `fetch`、XHR 或 WebSocket。**这是早期源码级检查的当时记录**。本 PR 随后新增了独立 Chromium 自动化，见下方实测证据；自动浏览器通过仍不等于人工 Human 验收。当前可访问文件库没有原始 XLSX，本轮也没有获得登录后 Job JSON。后续严格按 U1–U6 的产品建议核对 Host 语义，并用真实 22 列、同名冲突、三行真实缺失、草稿恢复、可撤销忽略、预检与最终导入、移动/桌面/键盘/可读性提供证据。与 #860/#878/#846 已开放 BEX 工作隔离；本 Draft 不可作为 V2 已上线声明。
