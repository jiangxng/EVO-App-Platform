# 同步Session缺服务拒绝的兼容检查

## 目标与完成条件
manager/server.ts中显式静态身份或当前identity.session绑定缺有效Provider时明确拒绝，不能变成另一个兼容主体。

## 流程与步骤
有效静态身份仍可用；停用/卸载后受保护请求503，原enable/install恢复。无配置旧演示仍兼容；有效请求Bearer/Managed优先级保持，不新增登录/确认步骤。

## 导航与信息架构
原页面、路由、Provider管理及生命周期入口保持，不增加新认证模式、Agent工具或第二Provider试点。

## 视觉与颜色
无布局、配色、字体或token改动；复用已读Eidos权威。实际修改源为manager/server.ts的同步Session resolver分支，提供本记录满足Host源文件门禁。

## 记忆与注意力
系统保留当前显式身份/绑定意图，不因缺服务替换主体；错误沿原503显示，修复用既有管理入口。安装/初始化规则不改，不声称卸载后重启保持未装。

## 无障碍与跨年龄
原键盘、焦点、标签和错误呈现保持，无新增需要记忆的操作。未执行浏览器/设备/屏幕阅读器或Human验收。

## 安全与数据修复
只对当前SYSTEM/default INSTALLATION绑定应用拒绝，不扩大其他作用域；不回退匿名/旧身份，无新权限或数据写入。共享身份、授权、Secrets来源不复制、不绑定某个UI启停。

## 证据与剩余问题
本地原managed 8项、六场景原函数前后对照及语法通过；新增7项Host覆盖作用域、真实HTTP生命周期/重启及Bearer优先级，由最终head CI验证。A05正式策略/其他入口、R1/R2/R3其余/R4仍OPEN；未部署/Human验收。
