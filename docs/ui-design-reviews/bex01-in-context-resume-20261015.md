# BEX-01 导入任务恢复：真实 Host 页面改动的 Human UI 审核

> 本次业务代码位于 `apps/data-import/page.ts`，新增独立回归 `tests/protocol/bex01-in-context-resume.test.mjs`。Eidos 的正式交互原则已通过 [eidos PR #186](https://github.com/jiangxng/eidos/pull/186) 进入 main。本 PR **不是** #909 合成高保真 HTML，也**不**替代 #860/#878 映射/字段创建实施窗口。

## 目标与完成条件

企业业务人员打开“数据导入”，能够立即看到本企业已有的、当前可用目标下**未完成的导入作业**，优先继续上次的工作；字段选择由持久的导入 Job/Recipe 保存，而不是浏览器草稿。选择继续之后导航至正确的既有业务页面，**没有导入/提交的副作用**。

## 流程与步骤

保持现有服务 `DataImportService` 的 STAGED / DRY_RUN_FAILED / DRY_RUN_READY 生命周期和既有路由，不新造 Job 状态、保存引擎或另一个导入向导。页面按“未完成优先、各类按创建时间”重排最近作业，显示一个主操作“继续导入 · 文件名”：STAGED→字段核对；DRY_RUN_FAILED / DRY_RUN_READY→预检查页面；最终提交仍必须在预检查页明确确认。完成或部分提交的作业不提供危险的“继续提交”快捷入口。

## 导航与信息架构

入口仍是原 `/data-import` 列表。不增加顶级导航、重复功能入口或 Agent 对话要求。当前可用导入目标由调用页面的 Host 上下文提供；针对不可用目标的旧 Job，不生成新的恢复快捷操作。即使记录数很多，未完成任务也排到前面，不再被最近二十条成功记录挤出可见范围。

## 视觉与颜色

沿用 Eidos 既有 Catalog Browser 列表、主按钮与状态风格，不新增私有 CSS、色值、导航 Chrome 或渐变。页面保留现有文件名、记录数、业务状态；快捷继续才会取代“新建导入”作为当前唯一全局主动作，未完成 Job 的行内操作属于该行的上下文操作。

## 记忆与注意力

“功能就近、信息就地、系统记忆、异常驱动、操作连续”应用到已有 Host 作业列表：不要求用户重新上传未完成文件，不从几十条历史查找作业；直接返回当前作业已保存的映射或预检查；不虚构一个浏览器 localStorage “正式持久化”。此改动只改善入口，真实身份/银行字段异常依然通过原有流程与后续 BEX 页面处理。

## 无障碍与跨年龄

使用 Eidos 的语义导航 action 与 Catalog Browser 已有焦点、键盘和响应式规则，短动作文案中英双语。新操作支持基于路由的普通点击、键盘选择；本轮不修改独立 Eidos 组件或触摸命中区。后续需要基于真实 Host 中文桌面/手机页面进行 Human 视觉复核；仅编译或协议测试通过不能宣称真机可访问性签收。

## 安全与数据修复

- 只用传入的当前企业/授权上下文 Job 和已可用 target 生成便捷导航，不跨企业查询或扩大许可。
- `COMMITTED`、`COMMITTED_WITH_ERRORS` 不可恢复为“未提交草稿”；避免二次提交和双重写入。只有 STAGED / DRY_RUN_FAILED / DRY_RUN_READY 可以继续查看。
- UI 只生成路由，不调用 stage/validate/commit，更不推断缺失主体类型、自动创建 Schema 或更改来源 Excel。所有写入仍受既有授权、预检查和明确确认保护。
- 导入列表不做原件删改；失败后按既有后端状态恢复。
