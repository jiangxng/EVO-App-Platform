# DLP/EC请求时凭据兼容检查

## 目标与完成条件
修改`manager/server.ts`及`manager/memory-credential-fetch.ts`，只将原DLP/EC可选token读取移到原实际请求端口；未使用不解密，资格/绑定/设置或Abort改变后不发迟到请求。semantic共享reader合同留下一批，不扩展Agent功能。

## 流程与步骤
原安装、启用、Secret保存/删除、授权和审计入口保持，无新增步骤。未配置token仍可匿名请求；已配置但读取失败必须拒绝，不自动回放业务请求或降级匿名。失败后通过原显式保存或下一次合法调用恢复。

## 导航与信息架构
没有新增导航、页面、设置项、默认路由。原P12配置自动bootstrap安装行为未变，作为治理剩余资格单列；不把配置存在当作全部生命周期合格。settings只修改既有Secret，不重建无变更的端点runtime或连带semantic解密。

## 视觉与颜色
无布局、字体、Eidos token、色彩或交互控件修改。复用此前全文读取的Eidos Human Experience Authority和八项检查清单，没有新设计体系或外网研究。server.ts属于仓库UI源门禁，随本批提供此兼容评审。

## 记忆与注意力
停用和卸载不删除密文；重新启用沿用共享权威。配置型health依旧只描述URL，不证明凭据或远端健康。用户不需记住token或重新输入已有Secret；旧请求因上下文变化拒绝后由原动作显式重试。

## 无障碍与跨年龄
原字段、标签、焦点、键盘和触控路径保持。没有增加跨页记忆或手工命令要求。未执行浏览器、屏幕阅读器、设备或Human验收，不用自动CI代替体验签署。

## 安全与数据修复
保留原管理员验证、授权、加密存储与非Secret审计。每次异步读取后检查原Provider选择、epoch、Abort与共享Secrets runtime；只为两个owner保存有界整数。设置写入前阻止旧请求，finally释放计数；坏写不承诺原store事务回滚，显式重试可恢复。明文只用于单次请求，不声称JS字符串擦除。

## 证据与剩余问题
本地新9项组件加前批10项共19项通过，Host/fixture及server擦除语法通过。新真实Host用例以crypto实际解密计数检查启动/发现/保存/启停/重启、实际调度请求、写失败恢复、删除匿名和绑定切换；正式构建、Host实际运行结果及准确head由本PR CI保存。未部署、真实外网或Human验收；semantic、R1/R2/R4及其他Provider继续开放。Help分类：原Secret操作与拒绝说明仍有效，无新增操作路径；本次时机/竞态限制已记录治理说明。
