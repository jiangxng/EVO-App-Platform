# 本地工作台刷新后导航入口更新 — UI Review

## 目标与完成条件
本地体验者在 `localhost:4100` 刷新已打开的工作台后，应看到当前构建的活动栏；已删除的全局“工作区”图标不应从旧脚本缓存中重现。应用图标仍负责展开或收起应用导航。

## 流程与步骤
用户继续使用原有页面，只需普通刷新。`scripts/local/host.mjs` 在启动时从构建生成的浏览器资源清单计算版本号；构建内容变化后，首页引用新的资源地址。无需用户运行清缓存命令或记住额外步骤。

## 导航与信息架构
沿用 #1120 已合入的去重：活动栏只有“应用”等当前有效入口，不恢复第二个全局“工作区”入口。本次更改只让本地浏览器读取已合入的导航代码，不增加页面或菜单。

## 视觉与颜色
没有修改 Eidos 的布局、图标、颜色或 tokens。当前源码和构建产物中的活动栏配置已无重复入口；资源刷新后应呈现同一套已审核的工作台视觉。

## 记忆与注意力
页面地址和工作上下文保留。构建版本由启动器自动计算，用户无需记住旧构建版本，也无需判断应清除哪个脚本缓存。

## 无障碍与跨年龄
既有活动栏的键盘、焦点、文字缩放和触控行为不变。资源更新只改变浏览器请求的版本化地址；实际桌面、移动和辅助技术体验仍需真实页面验证。

## 安全与数据修复
本地版本只由已生成的浏览器资源清单决定；不改会话、权限、插件安装状态或业务数据。原有 immutable 资源缓存和旧版本归档仍由 Host 管理；若启动时缺少清单则启动失败，避免以固定 `dev` 版本继续提供过期资源。

## 证据与剩余问题
来源：用户提供的 `localhost:4100` 截图；#1120 已合入的 `manager/desktop-workbench-runtime.ts` 去重；本次 `scripts/local/host.mjs` 与 `scripts/local/asset-revision.mjs` 修改及 `tests/local/asset-revision.test.mjs`。本地构建与资源版本回归测试结果在 PR 中记录。浏览器访问曾被当前会话的安全策略拒绝，因此真实页面截图和 Human 确认待用户刷新后完成，不能以代码测试冒充视觉签收。
