# BEX-01 V3｜批次固定值：主体类型的人工确认、保存与恢复（2026-10-16）

> 本次变更源于用户提供的 V3 原型截图及 [原 V3 HTML（Draft #909）](https://github.com/jiangxng/EVO-App-Platform/blob/docs/bex01-v2-human-design-review-20261015/docs/plans/foundation-list-experience/BEX-01-IMPORT-V3-IN-CONTEXT-HIGH-FIDELITY-20261015.html)。#984 已将集中审核的四列结构接入真实 Host。本轮只补最核心的「批次固定值可人为决策→写入已有 Import Job→重新进入恢复」，**不能把供应商关系推断为全是机构，也不能把已有 Excel 列的混合数据强制变成同一个值。**
>
> 精确变更的 Human UI 源：`apps/object-extension/batch-page.ts`；Host command 决策：`apps/object-extension/batch-action.ts`；协议测试：`tests/protocol/bex01-batch-extension-import.test.mjs`。沿用已授权的批量创建命令和 Import Job CONSTANT 结构，不增插件/路由/数据表/全局 Eidos CSS。

## 目标与完成条件

企业字段导入的业务审核者需要明确判断本批每一条对象是否具有同一「主体类型」值。V3 页面必须默认**不设置**；只有 Human 明确选择经当前往来对象正式 Schema 支持的 `ORGANIZATION` 或 `PERSON`，并在原批次确认时，才形成真实持久化的 `{targetFieldId:"subjectType",transform:{kind:"CONSTANT",value:...}}`。已保存值再次进入自动回显，不能丢源 Excel。

## 流程与步骤

当 **未存在**对 `subjectType` 的来源列映射时，审核页顶部提供「批次固定值 · 主体类型（应用于所有导入记录）」选择：不设置 / 机构 / 个人。默认不设置；已保存的值自动回显。做完字段复用/拟建/忽略后，需要原 `确认：批量创建并自动映射` 的显式动作。Host 先验证选项、与按列映射的冲突、全部字段决策，然后通过原 Import owner `applyMapping` 更新，旧 dry-run 自动失效，仍需单独预检查、行修复与最终导入确认。无新自动提交。

## 导航与信息架构

入口不变：`/data-import/jobs/:id/map` →「集中审核未匹配字段」。批次判断位于四列表上方，属于整个导入任务而非某个来源列。若已有真实来源列映射至 `subjectType`，仅显示“按来源列逐行读取”的只读说明并指向后续异常行修复；**不渲染覆盖全批的选择器**。业务字段列表仍保持 V3 四列、异常优先、证据就地展开。

## 视觉与颜色

使用现有 Eidos `form`/select 与语义组件，中文明确提醒“应用于所有导入记录”，也区分“来源列逐行读取”和“批次固定值”。不复制原型 CSS，不增加独立表单弹框，不把固定值藏在技术 Metadata 中。状态色、44px 触控、桌面/移动响应式仍遵循 Eidos 正式设计语言。

## 记忆与注意力

用户在批次页做过的决定按 Import Job mapping 恢复；不需要重新输入或回忆“之前选择的是机构还是个人”。其他历史批次映射全部保留。任何仅有 SUPPLIER 身份、但没有 Human 保存决策的任务，默认是「不设置」，而非擅自推断 `ORGANIZATION`。同时让该决定的适用范围（所有行）就近可见，防止理解为仅给缺失的三条补值。

## 无障碍与跨年龄

原生 select、文本标签和只读来源说明可由键盘/读屏器识别；选择项明确携带「机构／法人」「个人」中文，真实提交值使用 Schema 固定 ID。所有重要信息都以文字表述而非依赖颜色。窄屏/大字号及用户原始文件仍需浏览器与 Human 后续验收。

## 安全与数据修复

权限、企业 context、Job 状态、Host 动作、目标字段身份、角色关系及导入审批不变。若字段已按 Excel 来源列映射，伪造批次覆写动作将被服务器拒绝；未知值、已提交任务、重复目标与未解决审核均在字段定义创建**之前**拒绝。新的常量与现有映射合并持久化，原始行及表头绝不改写，成功后旧预检查必须重新执行。明确指出**这项常量对整批所有记录生效，不是“仅填补三条空值”功能**；混合来源的三条缺失主体类型依旧应该逐行纠错。

## 证据与剩余问题

测试验证必须覆盖：默认不设置、保存回显、原源行不变、已有按列映射不可覆盖、非法类型拒绝且零写入、Host 的原导入端到端无回归。PR 按精确 HEAD 全套 CI、Human UI 设计门禁与独立真实 Host Chromium 报告决定是否合并。已登录 Railway 客户真实 Excel 仍不可访问，因此隔离合成样例绿灯 **不等于** E4-03 原数据或 V3 Human 最终签收。企业字段审批就地方案预览、状态随前端操作即时更新和未提交草稿跨页恢复需独立验收，不能假装此次全部解决。
