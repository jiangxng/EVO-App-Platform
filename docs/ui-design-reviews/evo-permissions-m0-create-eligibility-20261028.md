# EVO 权限 M0：企业创建资格与友好提示 UI 设计评审

## 目标与完成条件
用户从企业目录进入创建企业时，应提前看到真实当前权限；权限不足不出现可提交表单或原始 STATIC_POLICY_NO_MATCH。已有的创建成功路径保持原先的表单与动作契约。此记录只代表代码设计评审，不是 Human 签收。

## 流程与步骤
企业目录 → 读取当前请求身份与授权 Provider → 有资格显示创建按钮；无资格给出直接解释和“我的权限”入口。即使绕过目录直接访问新建路由，后台仍根据当前身份与个人上下文返回明确引导（无业务写入）。“我的权限”仅提供创建企业的只读资格状态和合法的创建入口。提交时继续执行原有的需要人类确认、个人上下文与服务端授权检查。

## 导航与信息架构
沿用原有企业上下文治理插件（未安装则不贡献页面），在该插件内增加“我的权限”路由，不在平台设置页制造空的权限分类，不给未安装插件生成任何菜单。平台级管理员管理页仍属于下一个 M2 里程碑，不在本轮出现虚假管理功能。

## 视觉与颜色
使用原有 Eidos CatalogBrowser 和表单，不增加 CSS、颜色或第二套组件。无需权限的状态以文字提示呈现，不用空白画布或原始错误代码。改动源：apps/enterprise-context-governance/context-page.ts、package.ts、constants.ts、manager/enterprise-create-eligibility.ts、manager/server.ts。

## 记忆与注意力
中文界面以“当前账号尚未获得创建企业权限，请联系平台管理员”说明下一步；从企业目录进入“我的权限”无需记忆内部授权代码。允许、拒绝、未登录、切换个人空间、服务暂不可用均分别说明。

## 无障碍与跨年龄
复用 Eidos 语义标题、标准导航动作及可读空状态，无新增自定义按钮或颜色编码作为唯一状态表达。桌面实际键盘/读屏、触屏和 Human 验收仍待进行，不冒称通过。

## 安全与数据修复
服务端创建动作仍走原有 authorizeMaterialWriteV010 与明确确认；“我的权限”只读，不返回权限规则原文、不持久化任何授权。预检只作提示，提交时重检防止撤权后竞态。无身份、Provider 缺失/异常时失败关闭。绝不将东京共享 demo-user 提升为 Platform Owner。

## 证据与剩余问题
针对性自动测试 tests/protocol/enterprise-create-eligibility.test.mjs 覆盖至少四类状态、直接页面与目录联动、缺省拒绝以及服务端动作检查。CI/合并/东京部署/真实账号与 Human 另行核验。M1 身份、M2 平台授权写界面和 M3 端到端不在本 PR。
