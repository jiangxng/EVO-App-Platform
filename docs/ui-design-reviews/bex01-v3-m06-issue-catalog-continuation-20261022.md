# BEX-01 V3 / M06｜超过 12 条问题的完整导览（2026-10-22）

## 边界与结论
沿用 #1086 `9a1962a` 的 16/16 自动化证据和既有工作台，不复做 M01–M03。源码核查发现 `reviewIssues.slice(0,12)` 静默截断了 Host 导入问题概览；其中包括待判断来源列及已完成 dry-run 的行级校验。原表中来源列可查看，但概览第 13 项后无法直接访问，是确实存在的功能缺口。

本批仅为 **Eidos workbench 显式选用** `reviewTask.issuesPageSize:12`：保留全部经过验证的 Host 问题，默认展开前 12 项，之后每 12 项用原生 `details/summary` 按顺序折叠。真实行纠错链接仍必须由原有 Host 授权，不能生成虚假路由；只有来源定位的项目仍触发原来的 Form 行定位。问题数来自完整 Host 集合，不随未保存的本地字段选择减少。

## 保守约束和回归门
- 其它 Eidos 应用保持 12 项旧限制和既有 DOM；新增多页 opt-in 只有 `workbench` 可用。
- 可选完整目录上限 **4096** 项，超出时验证失败而非静默丢失。极大导入需要 Host 进一步定义服务端分页，不能声称无限扩展。
- 每一项标题、描述、焦点 group、已授权行链接仍走原有校验；`summary` 支持键盘、无脚本也能展开；没有新 Host 命令、隐式保存或动态授权。
- 29 项合成任务检查：首页 12 项、后续 13–24 与 25–29 两组、最后一项可定位；错误分页值、非 workbench 越权、旧视图超 12、超 4096 均应拒绝。
- 完整 `protocol-and-core`、`lightweight-host`、真实 Chromium 的结果以新 HEAD GitHub Checks 为准；未通过前不称完成。
