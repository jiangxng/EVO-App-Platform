# EVO 插件设置首页：无插件时不显示空分组（2026-10-27）

## 目标与完成条件
东京新环境截图显示固定四组：业务管理、应用与扩展、AI 与知识、系统，以及未经本地化的 SETTINGS_GROUP。目标是没有已安装且可配置的插件时，设置首页不显示这些分类及不可达入口；插件安装后设置自动出现。截图是用户提供的现场证据，本记录不是上线签收。

## 流程与步骤
用户进入设置 → Host 读取真实安装状态和插件声明的配置能力 → 有可配置插件才出现设置分类与条目；没有时说明“暂无已安装插件的设置”，提供“前往插件商店”，不伪造安装记录、企业 Context 或 Provider 健康状态。停用后的已安装插件配置仍可查看以便修复；卸载后条目消失。

## 导航与信息架构
业务页面、插件商店和企业/账本管理入口属于各自应用，不等于插件的 Settings Contribution。设置不再凭硬编码固定四组或其他 App 的页面路由推断配置能力。保留设置 Home 和有真实配置贡献的插件页面，以 Host 的 installedPackages 与声明的 settings/secrets 为准。变更源码：manager/settings-page.ts。

## 视觉与颜色
复用既有 Eidos CatalogBrowser，无新 CSS、固定颜色或重复导航。空页只显示简洁说明和一个插件商店入口，避免四张大面积空卡。移除可见生硬的 SETTINGS_GROUP 分类标识。

## 记忆与注意力
用户无需自行判断空分类是不是安装成功。系统动态发现可用配置；从商店安装后再返回设置就能找到对应条目。提示不宣称后台一定完全未安装任何包，只表达没有符合当前配置展示条件的插件。

## 无障碍与跨年龄
沿用 Eidos 标题/空状态与语义 navigate 动作、键盘导航与已有移动布局；没有新增独立交互控件。尚待浏览器、读屏、触摸 Human 复核。

## 安全与数据修复
插件生命周期、授权、Secrets、设置读写校验保持原样。不会将禁用/未安装的可写权限变为有效，也不删除东京数据卷、改 Railway、改其他 PA05/BEX/Eidos/EC owner 代码。应用入口和设置入口是不同维度。

## 证据与剩余问题
源码与测试依据：manager/settings-page.ts，tests/settings/plugin-settings.test.mjs，docs/architecture/EVO-WORKBENCH-v0.1.md，用户上传东京设置截图。先记录 exact-HEAD CI，再分别验收部署与 Human 页面。是否已有真实自动安装包尚不能仅靠截图判断；本改动不假称已清理任何包。
