# 旧LLM凭据持久化触发兼容检查

## 目标与完成条件
本批修改`manager/server.ts`两个refresh函数，移除启动/普通设置刷新中的环境凭据自动put。旧环境变量仍可兼容推理；需要持久保存时使用已有API Key字段显式提交。删除Secret后刷新不得暗中复活。没有新页面、控件、Agent工具或模型功能。

## 流程与步骤
原设置页→填写API Key→保存→原管理员认证/授权与Secret审计流程保持。普通模型或Base URL保存不提交凭据，也不取得隐含迁移授权。启用/停用/重装和启动不代替用户执行Secret写入；没有新增确认框或聊天步骤。

## 导航与信息架构
复用原Package设置入口及`app-platform.update-settings`，不改变导航、路由、安装默认或Secret作用域。模型配置和共享安全服务仍独立于某一个UI插件的启停。

## 视觉与颜色
没有修改页面/Eidos、字体、颜色、布局或文案。沿用此前完整阅读的Eidos设计权威与清单，不开展重复外网研究。配置状态将如实显示是否已持久保存，环境回退不等于存储已配置。

## 记忆与注意力
已有密文及显式保存的Key在启停和重启后保留，不自动覆盖。环境Key保持只读兼容来源，不默默变成持久状态；若部署准备移除环境变量，应先在原Key字段显式保存。删除持久Key不能当成撤销部署环境变量。

## 无障碍与跨年龄
现有字段、标签、焦点、键盘/触控路径保持，无新增操作模式或记忆要求。未执行屏幕阅读器、物理设备或Human验收，自动Host检查不能代替这些证据。

## 安全与数据修复
Secret写入/删除仍走原管理员认证、有效授权、加密存储与审计；未授权保存不写，普通模型保存不迁移。共享Secrets及主密钥不按LLM停用删除。环境回退、已有密文读取、原Provider合同均保持，不承诺本批解决提前解密、在途取消、轮换冻结或全平台生命周期。

## 证据与剩余问题
新增真实Host回归覆盖未安装/停用/启用未使用、禁用重启、环境回退探测、普通设置零迁移、未授权拒绝、显式加密保存、无环境重启、删除不复活及审计。fetch仅合成.invalid端点，真实Host由本PR CI执行；本地12项既有组件与语法检查通过，未本地正式全仓build/Host/browser。最终结果见PR及Provider边界§6；固定7项4闭环3部分完成，未部署。
