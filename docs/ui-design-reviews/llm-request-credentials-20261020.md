# LLM请求时凭据绑定兼容检查

## 目标与完成条件
修改`manager/server.ts`和`manager/llm-credential-fetch.ts`，保留同步Provider选择和原工厂，只在实际infer/显式probe请求前解析Key。未用不解密；解析期间停用/重启用、保存配置或请求超时则不发迟到请求。不是Agent功能、UI改版或第二个Provider生命周期试点。

## 流程与步骤
原设置、安装/启用、推理与显式探测路径保持，不增加交互步骤。使用既有fetchImpl端口绑定请求授权头；设置保存期间请求拒绝，完成/失败后按实际配置恢复。环境Key仍只读回退，持久化仍需原显式Secret保存及原授权审计。

## 导航与信息架构
不增加导航、页面、工具、设置项或默认安装。同步resolveLlmProvider仍根据有效贡献、绑定和健康元数据选择，Agent/Human/Worker消费者合同不改。

## 视觉与颜色
没有页面、Eidos、字体、布局、颜色或文案变更。复用前批完整读取的Eidos设计权威及清单，无新视觉体系或重复外网研究。配置元数据不代表已解密或远端健康，UNKNOWN仍需显式探测/实际使用。

## 记忆与注意力
共享密文/主密钥仍保留，启停不清空数据；旧环境Key不会被自动写回。配置改变使旧请求上下文失效，避免旧端点取得新Key。错误后由原设置/显式调用恢复，不自动重放推理。

## 无障碍与跨年龄
原字段、标签、键盘/触控路径保持，没有新增记忆要求。未执行屏幕阅读器、物理设备或Human验收；本批仅有自动组件与Host证据，不冒称完整用户体验签署。

## 安全与数据修复
管理员Secret授权/审计不改。资格、配置版本和启停代际在每次异步读取后复查；到期signal不继续解密/联网。设置写入有计数门禁及finally刷新/释放，失败不重放WRITE。原Secret store写失败可能已改变内存，不声称事务回滚；共享安全服务不随单UI停用释放。

## 证据与剩余问题
本地新增9项与原12项合计21项通过；真实Host扩展通过test-only crypto解密计数检查启动/发现/启停/重启零解密和首次使用计数，强制真实文件写失败后显式恢复。正式构建/Node22/Host由本PR CI，结果见PR和Provider边界§7。未生产部署、真实LLM/外网或浏览器验收；在途网络取消/跨Host冻结及其他Provider仍未闭环。
