# 基础对象导入时准备目标字段

状态：开发评审；真实浏览器与 Human 签收待取得。变更来源：`apps/data-import/page.ts`、`tests/protocol/foundation-hx-model-entry.test.mjs`。用户原任务是在导入基础对象前完成建模；该入口服务于当前 Import Job 的未建字段，沿用现有 Object Extension 流程。

## 目标与完成条件

有权管理企业扩展字段的人，在核对当前来源文件时能看到主操作“保存选择并准备目标字段”，经原有提交动作打开当前导入任务的建模流程，再回到原映射。无权成员仍可核对已有字段；成功标准是当前文件、映射和原值均保留，建模与导入各有显式确认。

## 流程与步骤

在现有映射页识别待新增字段，主按钮明确提示下一步将准备目标字段。原有 DATA_IMPORT_REVIEW_COMMAND 保存选择并打开 Object Extension 的确认/批量入口，继续由其建议、草稿、发布与回跳流程承担业务操作；进入该入口本身不发布字段或提交业务行。

## 导航与信息架构

入口是原导入工作台的主操作及其已有路由，不增加工具菜单、全局菜单或独立“建模应用”导航。当前目标为往来对象、存在待新增字段且当前人有创建扩展字段权限时，主操作文案说明建模将发生在预检查之前。顶部原有两阶段导入进度保持原样。

## 视觉与颜色

复用 Eidos 已批准的主操作及 Business Office token。原 V3 的四列映射表、摘要指标与“需要处理”问题卡不因建模提示变更。页面仍只有一个前进主操作，避免增加此前已被用户要求移除的“字段处理工具”菜单。

## 记忆与注意力

原 DATA_IMPORT_REVIEW_COMMAND 携带当前 Import Job 和全部已保存选择；中断后由原已持久化任务恢复。返回映射后，已保存映射和源文件行保持不变。待新增列继续在“待新增字段”指标中，不重复计入“需要核对”的异常数，用户无需分辨同一列为何被算作两个问题。

## 无障碍与跨年龄

沿用 Eidos 带文字的主按钮，键盘与触控路径均应可达。中文文案直接描述下一步；窄屏不能隐藏该操作或必须横向滚动才能操作。真实 390px 与放大文字结果尚未取得，不能标为通过。

## 安全与数据修复

页面只根据 Host 提供的 `canCreateExtension` 调整主操作说明；Object Extension 发布时仍重新验证 Human 权限、企业上下文、来源版本和插件激活。原 Review 命令明确保存当前选择，导航本身不发布模型、不提交业务行。失败后返回原导入任务并保留来源和草稿，由原 owner 给出修正路径。

## 页面模式与导航归属

当前页是已有导入 Review 工作台；目标页是已有 Object Extension 的 Editor/Review 流程。此处沿用主操作，不创建新页面模式。V3 原型提供映射工作台的功能、布局和颜色参照；“建模”是用户后来提出的新业务动作，在原型中没有该动作，因此只在确实要新增字段时说明下一步，并保留原型其他结构。

## 入口、退出与恢复矩阵

| 身份/情境 | 入口 | 操作与目标 | 退出、取消或异常恢复 |
| --- | --- | --- | --- |
| 企业 OWNER/ADMIN，单个待新增列 | 当前导入映射页 | 主操作保存选择并进入原建模确认页 | 原建模页返回同一映射任务；取消不修改已存映射 |
| 企业 OWNER/ADMIN，多个待新增列 | 当前导入映射页 | 主操作保存选择并进入原批量建模页 | 原任务保留来源行与映射；失败可恢复草稿 |
| 无建模权限的企业成员 | 当前导入映射页 | 不显示建模文案；可继续核对有权限的字段 | 后端拒绝直接构造的发布请求 |
| 个人上下文、停用插件、来源漂移 | 有效路由由 Host 判定 | 无有效授权或来源时拒绝提交 | 业务错误定位到原任务，由有权者修复后重试 |

入口：当前 Import Job 的映射页。
退出：原 Object Extension 发布后返回映射页，或取消回到导入任务。
异常恢复：重新加载原任务及草稿，过期来源重新预检；实际浏览器证据待取得。
