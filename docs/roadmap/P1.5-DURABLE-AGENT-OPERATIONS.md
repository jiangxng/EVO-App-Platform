# P1.5 Durable Agent Operations

**Status:** COMPLETE — P1.5A HUMAN LIVE PASS / P1.5B HUMAN LIVE PASS / P1.5C PLATFORM AUTOMATED ACCEPTANCE PASS  
**Date:** 2026-09-27  
**Predecessor:** P1.4X Human LIVE PASS

## 1. Why P1.5 exists

P1.4X proved the Personal Agent vertical experience with a real LLM and real governed Memory behavior.

It also exposed three infrastructure gaps that should not remain implicit:

1. ranked Memory search/recall is not deterministic inventory;
2. domain-specific proposal readback is not a generic durable receipt for Agent side effects;
3. a single synchronous Agent HTTP request has shown a practical ~60 second ceiling.

P1.5 turns those observed constraints into explicit platform capabilities.

## 2. P1.5 invariant

```text
Retrieval finds relevant knowledge.
Inventory establishes governed completeness.
Receipts establish durable side-effect continuity.
Runs establish resumable execution.
```

Do not make one mechanism impersonate another.

## 3. Slice plan

### P1.5A — Context Memory Governance Inventory

Goal:

Provide deterministic, paginated, Host-authorized enumeration of governed Context Memory.

Required properties:

- current Host-resolved Context only unless a separately authorized governance scope exists;
- deterministic ordering independent of relevance scoring;
- stable pagination/cursor semantics;
- explicit completeness semantics;
- explicit visibility treatment for ACTIVE / RESTRICTED / EXPIRED and canonicalized/superseded records;
- exact IDs and immutable provenance available for audit;
- no semantic search or query-expansion requirement;
- ordinary ranked search/recall behavior unchanged;
- Agent/tool descriptions explicitly distinguish INVENTORY from RETRIEVAL.

Primary use cases:

- duplicate-set discovery;
- contradiction/governance review;
- “how many governed records exist?” questions;
- audit/export preparation;
- proof that a ranked recall result is or is not complete.

P1.5A is the first implementation slice.

### P1.5B — Generic Durable Agent Action Receipt

Goal:

Every material Agent side effect has a durable Host-owned execution record instead of relying on domain-specific readback.

Minimum receipt fields:

```text
actionId / invocationId
principal / actor
resolved Context
tool / action id
effect
requestedAt
completedAt
status
idempotency key
input digest
result entity references
error/result summary
provenance / audit metadata
```

Rules:

- Host owns receipts, not the LLM;
- receipts do not replace domain authority;
- retries must resolve through idempotency/receipt state;
- Personal Agent can inspect prior action completion without repeating a WRITE.

### P1.5C — Resumable Agent Runs

Goal:

Longer Agent work must not depend on one browser-to-server HTTP connection staying open.

Required direction:

- durable run ID;
- resumable state machine;
- bounded step execution;
- progress/readback;
- idempotent continuation;
- explicit terminal states;
- browser reconnect/resume;
- no hidden background authority escalation.

This addresses the ~60 second synchronous request ceiling observed during P1.4X.

## 4. P1.5A acceptance

P1.5A is complete only when:

1. inventory is deterministic and paginated;
2. page/cursor behavior has regression coverage;
3. inventory scope is Host-authorized;
4. governance visibility semantics are explicit;
5. canonicalized/superseded history semantics are explicit;
6. ranked retrieval remains separate and unchanged;
7. Personal Agent can use the inventory surface when completeness matters;
8. Human browser can ask a completeness-sensitive Memory governance question without the Agent pretending ranked recall is exhaustive.

## 5. Non-goals for P1.5A

Do not add:

- semantic embeddings as an inventory dependency;
- automatic duplicate truth decisions;
- automatic deletion of duplicate/history records;
- cross-Context enumeration without explicit authority;
- generic physical deletion;
- a new Memory content model.

## 6. Architectural fit

P1.5 preserves the established boundaries:

```text
LLM
= reasoning / query formulation / explanation

Host
= authority / scope / durable state / inventory / receipts / runs

Context Memory
= immutable governed knowledge

Eidos
= interaction surface
```

Do not begin P1.5B or P1.5C until P1.5A has a stable contract and CI evidence.

## 14. P1.5C active direction

P1.5C now becomes the active slice.

The design must split long Personal Agent work into bounded durable execution slices:

```text
run create
→ durable runId
→ one bounded model/tool slice
→ persist
→ return
→ resume(runId)
→ next bounded slice
→ ...
→ terminal run state
```

A browser connection is transport, not run lifetime.

P1.5B Action Receipts remain the idempotency/safety boundary for material WRITEs during resume.


## 15. P1.5C automated platform closure — 2026-09-28

P1.5C has no new user-interface surface. Under the Human-approved testing policy, backend/run semantics were accepted through automated Host/action tests plus production deployment evidence rather than requiring a redundant browser click-through.

Final implementation:

```text
enterprise-agent.run.start
enterprise-agent.run.get
enterprise-agent.run.resume
enterprise-agent.run.list
```

Durable properties verified automatically:

- durable `runId` and Principal/Context ownership;
- append-only run events;
- one model decision per bounded resume slice;
- model decision durable before tool execution;
- tool observation durable after execution;
- JSONL reconstruction after process restart;
- resume without resending the original task;
- same Provider/model pinning;
- current Principal/Context re-check on every resume;
- concurrent resume rejection;
- indeterminate P1.5B WRITE receipt fails closed;
- successful WRITE replay reuses Action Receipt and does not repeat the side effect;
- `SLICE_STARTED` crash before model decision resumes inside the same durable slice;
- append order, not wall-clock time, is the causal event order.
