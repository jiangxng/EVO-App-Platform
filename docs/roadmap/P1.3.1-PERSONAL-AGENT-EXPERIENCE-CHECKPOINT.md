# P1.3.1 Personal Agent Experience Checkpoint

**Status:** historical first checkpoint; superseded by P1.4X

> Current Human browser runbook: `docs/roadmap/P1.4X-PERSONAL-AGENT-VERTICAL-EXPERIENCE-CHECKPOINT.md`. P1.4X fixes the local authorization/bootstrap-secret setup gap and extends the experience through quality, contradiction and Follow-up.
**Date:** 2026-09-27

This checkpoint is the first product-level walk-through of the Person-first Personal Agent stack. It uses only production contracts and Host-owned state. There is no demo-only readiness, fake Provider state, browser-owned Secret state or Memory bypass.

## Goal

Walk this real lifecycle in one browser:

```text
Plugin Store
→ Install Personal Agent
→ Needs setup
→ Set up
→ install/select LLM Provider
→ configure Provider + API Key through Host Secrets
→ Host resolves Provider
→ Ready
→ Open Personal Agent
→ choose Context
→ Chat
→ Memory Review
→ Memory Governance
→ Memory Source Health
```

## 1. Start the integrated App Platform

From `jiangxng/EVO-App-Platform`:

```powershell
git checkout main
git pull
npm ci
npm run build
$env:APP_PLATFORM_STATE_FILE="./.local/app-platform-state.json"
npm start
```

Open:

```text
http://localhost:4100
```

`APP_PLATFORM_STATE_FILE` makes Package lifecycle, settings, encrypted Host Secrets and the P1.3 Memory governance sibling state files durable across restarts.

Do not put the OpenAI API Key in an environment variable for this checkpoint. Configure it through the browser so the Host Secrets experience itself is exercised.

## 2. Install Personal Agent

1. Open **Plugins**.
2. Find **Personal Agent**.
3. Press **Install**.
4. The same real Plugin Store surface refreshes after the successful lifecycle command.
5. Personal Agent should now show **Needs setup** and the primary action should become **Set up**.

PASS means the UI state is derived from Package lifecycle + `evaluatePersonalAgentReadinessV010`, not from a UI-local flag.

## 3. Install the LLM Provider

1. Press **Set up**.
2. The **LLM Provider** step should be current.
3. Press **Open Provider catalog**.
4. Install **OpenAI LLM Provider**.
5. Return to **Personal Agent** and open **Set up** again.

The Provider configuration step should now be current.

## 4. Configure the Provider through Host Secrets

1. Press **Configure Provider**.
2. Keep or change the model/base URL.
3. Enter the OpenAI API Key in the Secret field.
4. Secret changes require bootstrap administrator authentication. For the current local experience use the P1.4X launcher, which prints the local **Administrator authorization** value.
5. Save.

Expected behavior:

- the saved API Key is never read back into the browser;
- the Secret status becomes **Configured**;
- the Provider runtime is refreshed from Host-owned configuration;
- Personal Agent readiness is recomputed from the effective Provider runtime.

Use **Provider status** when troubleshooting. It routes to the formal `llm.inference` Provider surface.

## 5. Reach Ready

Return to **Personal Agent → Set up**.

When Provider resolution is usable:

- every setup step is complete;
- the completion action is **Open Personal Agent**;
- the Plugin Store Personal Agent item reports **Ready** and its primary action is **Open**.

If the Provider is unavailable/degraded, use **Check Provider status** and **Recheck setup**. Do not bypass readiness.

## 6. Experience Personal Agent

Open Personal Agent.

Verify:

- Chat composer is enabled only when Ready/Degraded;
- the current Context is visible;
- only Host-offered Contexts appear in the selector;
- switching Context does not manufacture an Enterprise Context;
- a real LLM request goes through the selected `llm.inference` Provider.

Suggested first prompts:

```text
Explain my current context and what you can access.
What needs my attention right now?
```

## 7. Continue into governed Memory

From the completed Setup flow, or the Workbench Memory activity, open:

- **Review Memory** → `/enterprise-agent/memory`
- **Memory Governance** → `/memory`
- **Memory Source Health** → `/memory/sources`

These surfaces remain governed:

- proposals require Human Review before durable Memory;
- Search reads only through the Host Memory Reader;
- RESTRICTED / EXPIRED Memory is removed before ranking/UI candidates;
- Enterprise governance detail remains OWNER/ADMIN only;
- Source Health exposes Provider state but never Secret values.

## Acceptance

P1.3.1 is a successful experience checkpoint when one user can walk the lifecycle without source edits, SQL, fake data paths or manual internal API calls:

```text
Install
→ Needs setup
→ Provider install/configuration
→ Ready
→ Open
→ Context-aware use
→ Memory review/governance/health
```

Any friction discovered here should be fixed in the formal Package / Provider / Eidos / Host contracts rather than patched with a demo-only page.
